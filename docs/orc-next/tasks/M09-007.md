# M09-007 — Specify the external snapshot-to-trainer transform

**Status:** Planned — blocked on source-data availability
**Milestone:** M09 — Controller specialization

## Objective

Define a versioned, reproducible external transformation boundary for canonical Controller experience without changing source records or selecting a training backend by assumption. M09-006 measured an empty source, so the first dependency is operator-approved availability of genuine curated examples and a fresh canonical inventory/snapshot measurement.

## Dependencies

M09-001–006 complete. Before specifying data-dependent mapping or executing a transform, obtain a nonempty canonical Active snapshot through existing M08 curation and M09-001 authority. Record actual capability coverage and provenance. Do not fabricate examples or infer a required minimum, balance, or readiness threshold. The trainer-specific format remains conditional on separately qualified tooling.

## Scope

Inspect the existing typed experience schema, snapshot, production request/output builders and validators, and the M09-005 investigation. Document the minimum external record/message mapping, preservation of semantic inputs/outputs, source identity, immutable manifest, transform revision, deterministic ordering, reproducibility controls, and fail-closed handling of unsupported or invalid records. Distinguish a trainer-neutral contract from any framework-specific adapter. Identify unresolved mapping questions from actual source examples and the exact prerequisites for a later implementation.

If the source remains empty, stop at a factual dependency report and identify the normal supervised curation path; do not design fabricated data or implement a speculative transform.

## Required deliverable

A repository-grounded specification under `docs/orc-next/` with source evidence, proposed external format/manifest boundary, compatibility assumptions, unresolved prerequisites, and narrow independently reviewable implementation follow-ons. No production implementation is authorized by this task.

## Non-goals

No canonical data mutation, synthetic examples, automatic harvesting, dataset export or transformation execution, splitting, sampling, balancing, deduplication, ranking, weighting, readiness threshold, training, model download, trainer installation, backend selection, runtime dependency, model-default change, benchmark/gate change, storage redesign, embeddings, provider fallback, provider token hard cap, or Python runtime dependency.

## Acceptance criteria

1. Source authority and actual current inventory/snapshot evidence are recorded; empty data is not treated as usable training input.
2. Any proposed mapping preserves canonical typed semantics and identifies unsupported cases without invented examples or assumptions.
3. The external artifact/manifest boundary is versioned, reproducible, and separate from canonical storage.
4. Trainer-specific compatibility is explicitly conditional and does not silently select a backend.
5. No transformation, training, canonical mutation, or production behavior change occurs.
6. Remaining prerequisites and follow-on tasks are narrow, evidence-based, and independently reviewable.

## Required review

Independently verify source evidence, semantic mapping claims, manifest/reproducibility boundaries, and absence of premature implementation or backend selection. Documentation-only work requires no full code validation. Unexpected code changes require separate review.

## Completion evidence

Report exact inspected revision, source evidence, mapping/manifest decisions or deferral, unresolved blockers, changed files, and validation. Do not commit or push before independent review.
