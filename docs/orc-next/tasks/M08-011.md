# M08-011 — Add deterministic Controller experience dataset inventory

**Status:** Done
**Milestone:** M08 — Experience dataset

## Objective

Add one deterministic, read-only inventory view over the persisted M08 Controller experience dataset so Orc can inspect actual curation coverage before any export, splitting, balancing, or M09 specialization work.

The inventory is metadata inspection only. It must not reinterpret examples, infer training readiness, mutate lifecycle, export trainer records, or run Controller inference.

## Repository-grounded context

M08-001 established the canonical persisted `ControllerExperienceExample` substrate in the global registry with typed schema version, capability, verification basis, provenance, correction/outcome/quality metadata, created timestamp, and Active/Retired lifecycle. Existing application APIs already create, get, list, and retire examples.

M08-002 through M08-010 cover every current inference-backed Controller judgment module with capability-local curation adapters:

- `controller.task_recommendation`;
- `controller.recovery_recommendation`;
- `controller.plan_generation`;
- `controller.workflow_intake`;
- `controller.plan_review`;
- `controller.plan_revision`;
- `controller.memory_capture`;
- `controller.memory_maintenance`;
- `controller.memory_selection`.

## Scope

Add a typed read-only dataset inventory and the smallest `OrcApp` API required to obtain it from the canonical global-registry experience table.

The inventory reports the complete persisted dataset, not a caller-selected page, and exposes only deterministic metadata counts.

## Canonical inventory shape

The implementation provides versioned typed inventory structures with:

- inventory schema version;
- total example count;
- total Active count;
- total Retired count;
- deterministic per-capability summaries sorted lexicographically by exact capability string.

Each per-capability summary contains exact integer counts for:

- total;
- Active;
- Retired;
- `Accepted`;
- `Corrected`;
- `Rejected`;
- `OperatorAttestation`;
- `ExplicitCorrection`;
- `ExternalEvaluation`.

No percentages, floating-point ratios, scores, recommendations, rankings, readiness labels, or inferred quality classes are introduced.

## Data authority

The persisted canonical M08-001 rows are the sole authority. Inventory construction reads the complete global-registry metadata set, rejects malformed persisted metadata, counts each row exactly once, preserves exact capability strings, sorts capability summaries lexicographically, and validates aggregate invariants before return.

The inventory does not use runtime `MemoryKind::Experience`, project-local databases, task/run/review tables, workflow state, logs, filesystem state, or model output.

## Required aggregate invariants

For the whole inventory:

- `total == active + retired`;
- sum of every capability `total` equals global `total`;
- sum of capability Active counts equals global Active count;
- sum of capability Retired counts equals global Retired count.

For every capability:

- `total == active + retired`;
- `total == accepted + corrected + rejected`;
- `total == operator_attestation + explicit_correction + external_evaluation`.

Empty dataset is valid and returns zero totals plus an empty capability list.
