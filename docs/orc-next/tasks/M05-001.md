# M05-001 — Add read-only Controller planning capability

**Status:** Done
**Milestone:** M05 — Planning and Lead unification

## Objective

Move the first concrete Planner judgment path into the local Controller through a bounded, read-only planning capability while preserving current Plan persistence and Lead/Planner compatibility machinery.

## Result

Implemented `ControllerPlanningRequest`, `ControllerPlanningState`, typed `ControllerPlanResult`, and `OrcApp::propose_controller_plan` through the model-independent `LocalInferenceRuntime` boundary.

The implementation reuses canonical `PlanResponse` validation and the existing Planner structured schema. Controller planning is read-only: it does not persist plans, create/apply tasks, consume Lead decisions, mutate workflow state, invoke workers, or perform Git mutation. Qwen/GGUF/llama.cpp/backend details remain outside Controller/domain/application planning types.

Existing durable Plan records, application semantics, persisted lineage, and Lead→Planner workflow remain unchanged for later M05 migration.
