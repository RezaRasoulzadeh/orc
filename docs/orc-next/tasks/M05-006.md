# M05-006 — Add read-only Controller Plan revision generation

**Status:** Done
**Milestone:** M05 — Planning and Lead unification

## Objective

Generate a revised Plan through the local Controller from a current Controller-origin Plan whose latest actionable Controller-origin Plan review requires revision, while keeping generation strictly read-only.

## Result

Implemented bounded `ControllerPlanRevisionRequest`, typed `ControllerPlanRevisionResult`, and `OrcApp::revise_controller_plan`.

Eligibility is checked deterministically before inference: the Plan must be current, Controller-origin, in `RevisionRequested` status, and have the latest unsuperseded Controller-origin `RevisePlan` review with canonical persisted feedback. Parent/review identity remains trusted application metadata and cannot originate from model output.

Revision generation reuses `LocalInferenceRuntime`, canonical `PlanResponse` schema/parser, and deterministic validation. It is strictly read-only: no persistence, supersession, Lead/Planner invocation, task creation, approval/application, or workflow continuation. Legacy Planner revision behavior remains unchanged.
