# M06-010 — Add supervised Controller memory capture judgment

**Status:** Done
**Milestone:** M06 — Persistent memory

## Objective

Add the smallest read-only Controller judgment that decides whether one explicitly supplied, bounded candidate is worth storing as durable memory and, when appropriate, proposes one canonical M06-009 memory mutation intent without authorizing or executing it.

This task begins memory capture judgment. It does not make capture automatic and does not add consolidation, background observation, transcript ingestion, or implicit writes.

## Repository-grounded context

M06-001 owns typed durable User/Project/Episodic/Experience records and canonical persistence. M06-002 owns deterministic bounded `ControllerMemoryContext`. M06-003 through M06-008 integrate that context into existing Controller judgment seams. M06-009 adds the supervised write boundary: bounded typed `ControllerMemoryMutationIntent`, deterministic legality, opaque one-shot authorization, fresh-state validation, and execution exclusively through `MemoryService`.

The missing seam is judgment about a candidate before proposal authorization. Do not bypass M06-009 by giving inference a mutation service or by automatically executing a model decision.

## Scope

Introduce a capability-local, bounded read-only memory-capture request/input and result.

Required behavior:

- accept one explicit capture candidate supplied by trusted Orc/application code;
- candidate input contains bounded declarative content plus typed source/provenance context sufficient to judge whether it is durable memory; it contains no storage or execution handle;
- combine the candidate with the existing canonical `ControllerMemoryContext` so the Controller can detect obvious duplication/conflict with currently retrieved durable memory;
- keep current explicit candidate/source facts authoritative over historical memory;
- inference returns exactly one of two outcomes: `Ignore` or `ProposeMutation`;
- `ProposeMutation` contains exactly one bounded canonical `ControllerMemoryMutationIntent` suitable for the existing M06-009 proposal boundary;
- validate the returned intent deterministically before exposing the result, but do not authorize or execute it;
- the application seam may translate a successful inference result into the existing M06-009 proposal path only as an explicit separate step;
- empty memory context remains valid;
- all inference is read-only with respect to durable memory.

## Capture judgment rules

The Controller should propose durable memory only when the candidate has plausible future value beyond the immediate turn/workflow. It should prefer `Ignore` for transient status, raw logs, duplicate information, ephemeral execution details, unsupported inference, or content already represented by authoritative current memory.

Kind intent remains typed:

- `User`: durable operator preference/context that should apply across projects;
- `Project`: durable current-project fact/decision/context;
- `Episodic`: useful project-bound historical outcome/event;
- `Experience`: reusable cross-project lesson supported by the supplied candidate/source facts.

The Controller must not manufacture global truth from project-local evidence. Existing current project facts and explicit operator/source facts outrank conflicting historical memory.

## Invariants / requirements

- Reuse `ControllerMemoryContext`; no second retrieval model.
- Reuse `ControllerMemoryMutationIntent`; no second mutation schema.
- Keep capture request capability-specific; do not create a universal Controller request/state type.
- The model receives no `MemoryService`, `Database`, registry, filesystem, workflow, authorization, or execution handle.
- Capture inference cannot mint `ControllerMemoryMutationAuthorization` and cannot call M06-009 execution.
- Output is only `Ignore` or one proposed typed mutation intent.
- Existing M06-009 legality remains authoritative; a model-proposed intent does not become legal merely because inference returned it.
- Candidate/request, memory context, and combined inference input are independently bounded; combined serialized input maximum is 64 KiB.
- Structured output/result is bounded and schema-constrained before use.
- No implicit capture from existing Controller outputs, Plans, reviews, tasks, transcripts, worker results, logs, or lifecycle events in this task.
- No consolidation/correction/supersession inference over arbitrary existing memory sets yet.
- No semantic/vector retrieval, embeddings, learned ranking, background loop, model-specific domain behavior, or Python.

## Non-goals

- Automatically deciding when to invoke capture judgment.
- Automatically authorizing/executing a proposed memory mutation.
- Batch capture.
- Transcript/chat ingestion.
- Event subscriptions or background memory capture.
- Memory consolidation/deduplication workflows.
- Semantic search/embeddings.
- Interface UX.
- Training/fine-tuning dataset generation.

## Acceptance criteria

1. A bounded capability-local capture input accepts one explicit candidate plus canonical `ControllerMemoryContext` without persistence handles.
2. The Controller returns only `Ignore` or one `ProposeMutation` containing canonical `ControllerMemoryMutationIntent`.
3. Candidate/source facts remain authoritative over contradictory historical memory, and the prompt distinguishes User/Project/Episodic/Experience scope semantics.
4. Returned mutation intents are structurally/bounds validated but are neither authorized nor executed by capture inference.
5. A separate application seam can pass a proposed intent into the existing M06-009 proposal boundary without bypassing its deterministic legality checks.
6. Empty-memory behavior is valid; duplicate/transient candidates can be ignored without mutation.
7. Independent candidate/request and memory bounds plus a 64 KiB combined input bound reject oversized inference input before runtime invocation.
8. Capture inference and proposal generation cause no durable memory mutation and introduce no autonomous/background capture or consolidation.
