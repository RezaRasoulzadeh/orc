# M06-005 — Integrate bounded memory into normal Controller task recommendation

**Status:** Planned
**Milestone:** M06 — Persistent memory

## Objective

Feed the reusable M06-002 `ControllerMemoryContext` into the existing read-only normal task recommendation capability without changing task facts, recommendation schema, deterministic legality, authorization, or execution semantics.

M06-003 and M06-004 established the capability-local memory-input pattern for planning and recovery. M06-005 applies the same pattern to the original M02/M03 normal recommendation seam rather than forcing memory into `ControllerStatePacket` itself.

## Repository-grounded context

The normal recommendation path already has clear boundaries:

- `ControllerStatePacket` in `src/controller.rs` is the bounded canonical projection of current project/task facts;
- `ControllerStateBuilder::recommend` builds the packet from `ProjectOperations` and performs one read-only recommendation;
- `ControllerStateBuilder::recommend_packet` is the packet-level inference seam used by deterministic evaluation;
- `OrcApp::propose_controller_action` is the supervised application entrypoint that converts the typed recommendation into a bounded action proposal;
- deterministic action legality, one-shot authorization, and canonical mutation remain downstream in the existing M03 boundaries.

M06-002 exposes bounded typed memory through `OrcApp::controller_memory_context()`.

Use these seams directly. Do not redesign `ControllerStatePacket`, planning, recovery, intake, Plan review/revision, or action execution.

## Scope

Integrate memory into normal task recommendation only.

Required behavior:

- introduce a narrow capability-local recommendation input containing the existing `ControllerStatePacket` plus typed `ControllerMemoryContext`, or an equivalent wrapper that preserves the packet as the current-facts authority;
- `OrcApp::propose_controller_action` obtains memory through `controller_memory_context()` and passes it to the recommendation path;
- preserve current direct builder/evaluation helpers through explicit empty memory where appropriate;
- preserve typed memory identity/kind/scope/authority/provenance metadata in serialized model input;
- validate the combined recommendation input deterministically against a 64 KiB capability input bound while preserving the existing `ControllerStatePacket` validation and independent memory bound;
- empty memory remains valid;
- retrieval and inference remain read-only.

## Authority and precedence

The recommendation prompt/input must preserve this order:

```text
current ControllerStatePacket project/task facts and task contract
→ durable Project memory
→ durable User memory
→ Episodic project history
→ cross-project Experience memory
→ base model tendencies
```

Current packet facts always outrank contradictory memory. Project memory may provide durable project context. User memory is preference/context only. Episodic and Experience memory are historical guidance, never current task truth.

Memory may influence reasoning among valid recommendations, but it must not create a new recommendation kind, bypass typed recommendation parsing, alter kernel legality, authorize an action, or mutate state.

## Invariants / requirements

- Reuse `ControllerMemoryContext`; no recommendation-specific persistence model.
- `controller_memory_context()` remains the canonical application retrieval seam.
- `controller.rs` receives typed bounded memory, not database, memory service, registry, filesystem, or mutation handles.
- Keep `ControllerStatePacket` as the current-facts projection; do not embed durable memory into it or turn it into a universal Controller state type.
- Existing packet validation remains unchanged in authority.
- Combined recommendation input is deterministically bounded to 64 KiB and rejects oversized input before inference.
- `ControllerRecommendation` schema and typed suggested-next-step variants remain unchanged solely because memory was added.
- `controller_actions` proposal mapping, deterministic legality, authorization, execution, lifecycle mutation, validation, review, revision lineage, and economy behavior remain unchanged.
- No memory writes/capture/correction/removal/consolidation.
- No semantic/vector retrieval, embeddings, learned ranking, or model-based memory selection.
- No model-specific domain behavior.
- No Python.

## Non-goals

- Adding memory to intake.
- Adding memory to Plan review or Plan revision.
- Changing planning or recovery memory integration.
- Changing action-intent definitions or legality rules.
- Changing authorization/execution semantics.
- Automatically recording recommendations or outcomes as memories.
- Memory consolidation/deduplication.
- Semantic search or embeddings.
- Creating a universal Controller request/state type.

## Acceptance criteria

1. `OrcApp::propose_controller_action` supplies current bounded M06-002 memory through the existing normal recommendation path.
2. Recommendation inference retains typed memory identity/kind/scope/authority/provenance metadata.
3. `ControllerStatePacket` remains a distinct authoritative current-facts structure and is not widened into durable memory storage.
4. Current task/project facts and contract are structurally and prompt-level authoritative over contradictory memory.
5. `ControllerRecommendation` structured schema and typed decision variants are unchanged.
6. Deterministic action proposal mapping, legality, authorization, and execution remain unchanged and final.
7. Combined current packet + memory input is bounded to 64 KiB and oversized input is rejected before inference.
8. Empty-memory direct/evaluation behavior remains compatible.
9. Retrieval/inference causes no durable memory mutation.
10. No unrelated Controller capability is redesigned.
