# M02-001 — Build the read-only Controller state/recommendation path

**Status:** Ready  
**Milestone:** M02 — Read-only Controller

## Objective

Introduce the first read-only Controller slice that builds a bounded,
model-independent Orc project/task state packet, sends it through
`LocalInferenceRuntime`, and returns a typed recommendation. The Controller has
no mutation permission.

## Why

M01 proved the replaceable local inference boundary and its native adapter.
M02 now needs a narrow Controller-facing read path that gives the model enough
authoritative project/task context to make an inspectable recommendation while
leaving legality and execution in the deterministic kernel.

## Scope

- Add a `ControllerStateBuilder` over the existing `ProjectOperations` and
  selected `OrcApp` read APIs identified in `M00-REPOSITORY-MAP.md`.
- Add a bounded, serializable `ControllerStatePacket` containing deliberately
  selected project/task facts and bounded evidence summaries.
- Add a typed, serializable `ControllerRecommendation` that is advisory and
  inspectable; it must not execute or authorize a mutation.
- Serialize the bounded packet into a model-independent
  `LocalInferenceRequest`, call `LocalInferenceRuntime`, and translate the
  runtime response/error into the Controller-facing result.
- Add deterministic tests with a fake `LocalInferenceRuntime`; real GGUF
  inference remains optional and outside normal tests.

## Integration constraints

- Read project/task facts through `ProjectOperations` / selected `OrcApp` read
  methods only. The Controller must not hold a `Database`, issue SQL, or read
  SQLite directly.
- Keep Qwen, GGUF, llama.cpp, tokenizer, native handles and backend-specific
  settings outside Controller/domain types.
- Keep packet contents intentionally bounded: summaries, current/latest facts,
  bounded recent evidence and references only. Do not include full repository
  contents, complete history, transcripts, raw prompts or raw database rows.
- Preserve canonical lifecycle, validation, review, economy, permission and
  execution facts; the Controller may recommend but the deterministic kernel
  remains the authority for legality and execution.
- Do not add a mutation-capable Controller API, tool execution, or an implicit
  action dispatch path.

## Non-goals

- Do not add lifecycle mutation, dispatch, review, revise, accept or recovery
  operations.
- Do not add planning, Lead replacement or Planner migration.
- Do not add memory or memory retrieval infrastructure.
- Do not add model downloading, model management or Python dependencies.
- Do not redesign `OrcApp`, `ProjectOperations`, storage or lifecycle state.
- Do not dump the repository, full history or full transcripts into prompts.
- Do not require a real model file for deterministic validation.

## Dependencies

- M00-001.
- M01-002.

## Acceptance criteria

1. `ControllerStateBuilder` builds a `ControllerStatePacket` using only the
   existing `ProjectOperations` / selected `OrcApp` read APIs; the Controller
   has no direct `Database`, SQLite or SQL dependency.
2. `ControllerStatePacket` is model-independent, serializable and explicitly
   bounded. It contains selected project identity/repository facts, one
   selected task's canonical operational summary (including lifecycle and
   legal-next-step facts), contract/dependency context, and bounded execution,
   validation, review, economy and evidence references needed for read-only
   recommendation; it does not contain full repository contents, complete
   history, transcripts or raw database rows.
3. Packet bounds are enforced deterministically for collection counts, text or
   diagnostic sizes, and serialized packet size; tests prove oversized inputs
   are truncated or rejected according to the documented policy.
4. `ControllerRecommendation` is a typed, serializable, inspectable advisory
   result that can represent a suggested next step and rationale without
   exposing Qwen, GGUF, llama.cpp or native types and without granting a
   mutation capability.
5. The Controller submits only model-independent `LocalInferenceRequest`
   values through `LocalInferenceRuntime` and translates the typed runtime
   response/error without leaking backend-specific errors or handles.
6. Deterministic fake-runtime tests prove packet construction/serialization,
   recommendation propagation, typed runtime-error propagation and that the
   Controller path performs no lifecycle, database or other canonical mutation.
7. Normal tests require no network, model weights or native feature; any real
   GGUF exercise remains an explicitly opt-in smoke path.
8. Existing CLI/TUI/GUI and canonical kernel lifecycle behavior remain
   unchanged, and no scheduler, validation pipeline, economy resolver, memory
   system, Lead/Planner migration or tool execution is introduced.

## Required tests/evidence

- Unit/integration tests for bounded packet construction and serialization using
  temporary project data through the existing `ProjectOperations` / `OrcApp`
  read surfaces.
- Fake `LocalInferenceRuntime` tests for recommendation and typed error
  propagation.
- A no-mutation regression test covering the complete read-only Controller
  path.
- `cargo fmt --check` and `git diff --check`.
- Normal deterministic tests must run without a model file or network access;
  real GGUF inference is optional and must remain ignored/feature-gated.
