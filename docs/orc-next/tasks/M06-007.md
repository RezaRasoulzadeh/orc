# M06-007 — Integrate bounded memory into Controller Plan review

**Status:** Planned
**Milestone:** M06 — Persistent memory

## Objective

Feed reusable M06-002 `ControllerMemoryContext` into the existing read-only Controller Plan-review capability without changing canonical Plan/current-state facts, the three review outcomes, review persistence, approval/revision routing, or Plan application semantics.

M06-003 through M06-006 established capability-local memory inputs for Plan generation, recovery, normal recommendation, and workflow intake. The next smallest repository-grounded seam is `ControllerPlanReviewRequest` / `ControllerPlanReviewBuilder::review` / `OrcApp::review_controller_plan`.

## Repository-grounded context

`src/controller_plan_review.rs` already defines a distinct bounded review capability:

- `ControllerPlanReviewRequest` carries current Plan identity/version/status/origin, full bounded Plan response, current project/task state, project name, and optional operator resolution;
- request validation is bounded by the existing 64 KiB review-request limit;
- `ControllerPlanReviewBuilder::review` performs one read-only inference;
- output is restricted to `Approve`, `RevisePlan`, or `OperatorDecisionRequired`;
- result validation requires revision feedback for `RevisePlan` and keeps malformed output outside workflow authority;
- `OrcApp::review_controller_plan` deterministically verifies that the Plan exists and is the current valid Controller-review Plan before inference;
- review persistence, Plan status changes, approval, revision, application, workflow transitions, task creation, and worker mutation remain downstream kernel-owned boundaries.

M06-002 exposes bounded typed memory through `OrcApp::controller_memory_context()`.

Use these seams directly. Do not redesign Plan generation, Plan revision, intake, recovery, normal recommendation, persistence, authorization, or workflow routing.

## Scope

Integrate memory into Controller Plan-review judgment only.

Required behavior:

- introduce a narrow capability-local Plan-review inference input containing the existing `ControllerPlanReviewRequest` plus typed `ControllerMemoryContext`, or equivalent wrapper preserving the request as current-facts authority;
- `OrcApp::review_controller_plan` obtains memory only through `controller_memory_context()` after the existing deterministic current-Plan legality checks and passes it to the review inference path;
- preserve direct builder/evaluation helpers through explicit empty memory where appropriate;
- preserve typed memory identity/kind/scope/authority/provenance metadata in serialized inference input;
- preserve the existing independent Plan-review request validation and independent M06-002 memory bound;
- add an explicit deterministic 64 KiB bound for the combined review inference input; oversized combined input must be rejected before inference;
- empty memory remains valid;
- retrieval and inference remain read-only.

## Authority and precedence

The Plan-review prompt/input must preserve this order:

```text
current persisted Plan identity/version/status/origin and Plan content
→ current project/task state and explicit operator resolution
→ durable Project memory
→ durable User memory
→ Episodic project history
→ cross-project Experience memory
→ base model tendencies
```

For Plan review specifically:

- current persisted Plan facts and content are authoritative;
- current task/project state and explicit operator resolution outrank contradictory memory;
- Project memory may provide durable context for judging the Plan;
- User memory may provide preferences/context but cannot rewrite Plan content or operator resolution;
- Episodic/Experience memory is historical guidance only, never current Plan/project truth;
- memory may influence judgment among the existing three review outcomes but cannot create a fourth outcome, bypass structured parsing/result validation, persist a review, approve/revise/apply a Plan, or mutate workflow state.

## Invariants / requirements

- Reuse `ControllerMemoryContext`; no Plan-review-specific persistence model.
- `controller_memory_context()` remains the canonical application retrieval seam.
- `controller_plan_review.rs` receives typed bounded memory, not `Database`, `MemoryService`, registry, filesystem, workflow engine, or mutation handles.
- Keep `ControllerPlanReviewRequest` as the canonical current review facts; do not turn it into a universal Controller request.
- Existing current-Plan checks and request validation remain authoritative and deterministic before inference.
- Combined request + memory input is deterministically bounded to 64 KiB before inference; independent memory validation remains enforced.
- `ControllerPlanReviewDecision`, `ControllerPlanReviewResult`, strict output schema, and result validation remain unchanged solely because memory was added.
- Review persistence, Plan status mutation, revision/approval/application routing, task mutation, workflow transitions, authorization, and worker execution remain unchanged.
- No memory writes/capture/correction/removal/consolidation.
- No semantic/vector retrieval, embeddings, learned ranking, or model-based memory selection.
- No model-specific domain behavior.
- No Python.

## Non-goals

- Adding memory to Controller Plan revision generation.
- Changing Plan generation/intake/recovery/normal recommendation integrations.
- Changing review outcome definitions or revision-feedback requirements.
- Changing persisted Plan-review records or Plan workflow transitions.
- Automatically recording review outcomes as memories.
- Consolidation/deduplication.
- Semantic search or embeddings.
- Creating a universal Controller request/state type.

## Acceptance criteria

1. `OrcApp::review_controller_plan` supplies current bounded M06-002 memory through the existing Plan-review inference path.
2. Existing deterministic Plan existence/current-validity checks execute before inference and remain authoritative.
3. Review inference preserves typed memory identity/kind/scope/authority/provenance metadata.
4. `ControllerPlanReviewRequest` remains a distinct authoritative current-facts structure.
5. Current Plan identity/version/status/origin/content, current project/task state, and operator resolution outrank contradictory memory structurally and in the prompt.
6. The only review outcomes remain `Approve`, `RevisePlan`, and `OperatorDecisionRequired`; existing revision-feedback/result validation remains unchanged.
7. Review persistence, approval/revision/application routing, authorization, workflow mutation, and task/worker execution remain unchanged and final.
8. Existing request validation and independent memory validation remain enforced; combined review input is bounded to 64 KiB before inference.
9. Empty-memory direct/evaluation behavior remains compatible.
10. Retrieval/inference causes no durable memory mutation and no unrelated Controller capability is redesigned.
