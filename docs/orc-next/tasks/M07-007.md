# M07-007 — Compose one supervised Controller memory capture step

**Status:** Done
**Milestone:** M07 — Supervised autonomy

## Objective

Compose the existing M06-010 capture judgment, M06-009 mutation proposal/execution boundary, and M07-006 finite capture grant into one explicit application-level operation that processes exactly one caller-supplied capture candidate and may persist at most one eligible project-bound memory record.

## Result

Implemented in `309cfd72d9f780f27df3e37fda6d17f38284888a` and independently reviewed **PASS** with Luna + High.

The implementation adds `OrcApp::capture_controller_memory_once(...)`, which accepts exactly one `ControllerMemoryCaptureRequest`, one existing `ControllerMemoryCaptureGrant`, and one `LocalInferenceRuntime`, then composes the existing boundaries in this exact order:

1. `judge_controller_memory_capture(...)`;
2. `propose_controller_memory_mutation(...)` when capture proposes a mutation;
3. `inspect_controller_memory_capture_grant(...)`;
4. `execute_authorized_controller_memory_mutation(...)`.

`Ignore` returns without proposal, authorization, execution, mutation, or grant consumption. Every pre-authorization failure consumes zero. A successful M07-006 authorization consumes exactly one unit. Post-mint execution/fresh-validation/storage failure is not refunded. The path performs at most one inference, one proposal, one authorization mint, and one execution attempt, with no retry, fallback, alternate proposal, direct `MemoryService` mutation, grant replenishment, event wiring, or background capture.

The public composition result is state-safe: successful capture uses a privately constructed wrapper that can contain only canonical M06-009 `Mutated` state; execution rejection uses a private wrapper that cannot contain `Mutated`; and `ControllerMemoryCaptureStepError` variants intrinsically encode their stopping stage so callers cannot construct mismatched stage/error pairs.

M07-006 eligibility remains authoritative: only exact-current-project `Project`/`Episodic` Create proposals may be authorized. `User`/`Experience` and Correct/Supersede/Remove remain outside this capture path. M06-009 remains the only canonical mutation execution path and M06-010 inference schema/prompt/bounds are unchanged.

Validation reported focused M06/M07 regressions `83 passed`, `cargo test --lib` `409 passed`, `cargo test --features llama-cpp --lib` `415 passed`, both clippy commands passing with `-D warnings`, `cargo fmt --check` passing, and `git diff --check` passing. No inference contract changed, so no real-Qwen rerun was required.

## Architectural follow-up

M07-007 proves the full supervised capture chain for one explicit candidate, but automatic candidate derivation remains intentionally unresolved. `ControllerMemoryCaptureRequest` contains a full `MemoryDraft`, so deterministic workflow code must not invent durable memory content merely to enable automation; that would move judgment out of the Controller and into hardcoded policy.

The next smallest repository-grounded M07 seam is therefore separate supervised permission for M06-011 maintenance, not forced automatic capture candidate synthesis. Capture Create and maintenance Correct/Supersede/Remove remain distinct capability domains.
