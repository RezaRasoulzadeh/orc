# M09-004 — Define deterministic Controller candidate promotion gate

**Status:** Done
**Milestone:** M09 — Controller specialization

## Objective

Define a deterministic, model-independent candidate-vs-baseline comparison gate over validated M09-003 reports, fixing acceptance criteria before candidate training results exist.

## Completed scope

Implemented versioned typed comparison schema 1 in `src/controller_specialization_comparison.rs`, exposed through `src/lib.rs`, with supporting baseline/evaluation visibility changes.

The comparator validates both reports against the canonical M09-002 suite and requires exact suite schema, scenario count/order/identity/capabilities, expected semantics, acceptable alternatives, production request parameters, and semantically relevant runtime configuration. Model identity distinguishes candidate from baseline; self-comparison is explicitly non-promotable.

The gate requires strict global pass improvement, no execution/error increase, no capability pass-count regression, no baseline-passing scenario regression, no newly introduced Parse/Validation/Runtime failure for the exact scenario and class, and exact aggregate accounting. It produces typed deterministic decisions/reasons, exact signed deltas, and exact typed scenario transitions.

## Review and completion evidence

The initial independent review returned REVISE because coarse transition variants collapsed distinct outcome-class transitions. The revision replaced them with an exact typed baseline/candidate outcome pair, validated directly against scenario evidence. Exhaustive 25-pair tests and endpoint-tampering tests resolved the finding. Independent re-review returned PASS.

Reported validation: M09-004 focused tests 9 passed; M09-003 regressions 6 passed; M09-002 regressions 9 passed; standard library 434 passed; llama-cpp library 440 passed; integration tests passed; both clippy configurations, formatting, and diff checks passed.

No inference, production prompt/parser/runtime-setting, storage, OrcApp, workflow, memory, dataset, training, or model-default behavior changed. No architectural mismatch was reported. Canonical docs were untouched during implementation.

## Remaining boundary

The gate is deterministic acceptance evidence, not a statistical guarantee or automatic deployment authorization. No trainer/backend has been selected, no candidate has been trained, and no model has been promoted. Later M09 work must preserve the fixed gate and obtain actual comparable baseline/candidate evidence before considering a default-model change.
