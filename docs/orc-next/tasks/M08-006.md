# M08-006 — Add explicit typed curation for Controller Plan review

**Status:** Planned
**Milestone:** M08 — Experience dataset

## Objective

Add one capability-local curation adapter for an already-produced Controller Plan-review interaction, projecting the existing typed `ControllerPlanReviewInput` and existing canonical `ControllerPlanReviewResult` into one M08-001 experience example under explicit trusted verification metadata.

Continue the established M08 pattern without introducing generic experience-capture abstractions, automatic Plan-review harvesting, or labels inferred from later Plan persistence/revision/workflow outcomes.

## Repository-grounded context

`src/controller_plan_review.rs` already exposes a bounded typed reasoning boundary:

- `ControllerPlanReviewInput` contains the authoritative current `ControllerPlanReviewRequest` plus bounded advisory `ControllerMemoryContext` and exposes public `validate()`;
- the current request includes persisted Plan identity/version/status/origin, exact Plan content, current project/task state, project name, and optional operator resolution;
- `ControllerPlanReviewResult` contains exactly one semantic decision (`Approve`, `RevisePlan`, or `OperatorDecisionRequired`), bounded details, and optional bounded revision feedback and exposes public `validate()`;
- `ControllerPlanReviewResult::validate()` already requires revision feedback for `RevisePlan` and rejects empty supplied feedback;
- the inference boundary is read-only; review persistence, Plan status transitions, revision authorization, task application, and workflow routing are separate deterministic application/kernel work.

M08-001 remains the sole durable experience-record format. M08-002 through M08-005 established narrow capability-local curation adapters over existing production input/output contracts.

## Scope

Add one Plan-review-specific typed curation request and the smallest `OrcApp` API needed to persist one explicitly verified Controller Plan-review example.

The request must accept:

- one existing `ControllerPlanReviewInput`;
- one observed `ControllerPlanReviewResult`;
- one explicit accepted/expected `ControllerPlanReviewResult`;
- explicit `ControllerExperienceVerificationBasis`;
- explicit M08-001 outcome and quality metadata;
- optional M08-001 provenance;
- correction metadata only when observed and accepted canonical outputs differ.

Do not accept a caller-controlled capability identifier.

## Canonical capability

Use fixed code-owned capability identifier:

`controller.plan_review`

The caller must not be able to override it.

## Canonical input projection

The exact supplied `ControllerPlanReviewInput` is the dataset input authority.

Before projection:

- call existing production `ControllerPlanReviewInput::validate()`;
- serialize the exact typed input deterministically;
- preserve the exact current persisted Plan identity/version/status/origin/content, current state, operator resolution, and bounded memory already present in the input;
- do not rebuild a second Plan-review schema;
- do not re-read the current Plan, latest review, workflow, task state, or project state to replace the supplied input with later facts;
- do not summarize, reorder, enrich, truncate, or infer missing state.

No Plan-review inference call is permitted in the curation adapter.

## Canonical output projection

The existing `ControllerPlanReviewResult` is the dataset output authority.

Observed and accepted values must both pass existing production `ControllerPlanReviewResult::validate()`.

Persist the exact accepted result JSON as M08 `accepted_output`, including:

- exact `decision`;
- exact bounded `details`;
- exact optional `revision_feedback`.

Do not replace the reasoning result with a persisted `PlanReview`, Plan status, later revised Plan, workflow stage/status, task application result, or free-form prose.

## Provenance

M08-001 provenance remains optional, explicit, and non-owning.

Although `ControllerPlanReviewInput` contains persisted Plan identity, M08-006 must not synthesize M08 provenance from Plan/project/workflow storage. Dataset provenance remains caller-supplied metadata and must be validated only through M08-001.

Do not require provenance merely because the typed inference input carries Plan identity.

## Correction semantics

Compare exact canonical serialized observed and accepted `ControllerPlanReviewResult` values.

If observed == accepted:

- correction metadata must be absent;
- outcome must satisfy valid non-correction M08-001 semantics;
- no correction evidence is manufactured.

If observed != accepted:

- outcome must be `Corrected`;
- explicit valid correction metadata is required;
- `correction.original_output` must exactly equal the canonical observed `ControllerPlanReviewResult` JSON;
- M08 `accepted_output` must exactly equal the canonical accepted result JSON.

A correction may change decision, details, and/or revision feedback only through the explicit accepted typed result. Do not infer correction because the Plan was later approved, revised, persisted, superseded, applied, rejected, or produced successful/failed tasks.

## Verification boundary

Verification remains explicit and caller-owned.

Do not automatically treat any of these as sufficient verification or correction evidence:

- successful persistence of a Plan review;
- Plan status transition;
- subsequent Plan revision;
- later Plan approval;
- task application;
- workflow advancement;
- operator acceptance;
- eventual task/workflow success or failure.

These may become evidence for a future explicit curation policy, but this task must not derive labels from them.

## Production order

1. validate exact `ControllerPlanReviewInput`;
2. validate observed `ControllerPlanReviewResult`;
3. validate accepted `ControllerPlanReviewResult`;
4. deterministically project exact input/observed/accepted JSON;
5. enforce correction semantics;
6. construct exactly one `ControllerExperienceExampleDraft` with fixed capability;
7. delegate verification/outcome/quality/provenance/bounds validation to M08-001;
8. persist only through existing `OrcApp::create_controller_experience_example(...)`.

At most one row may be written per call. Any validation/projection failure must write zero rows.

- Controller Plan-review curation only; no generic experience adapter.
- Explicit trusted call only.
- No Controller inference.
- No automatic capture/harvesting.
- No Plan-review/workflow hook.
- No Plan/project/workflow lookup to refresh or enrich the supplied typed interaction.
- No automatic verification or correction inference.
- Fixed code-owned capability identity.
- Exact canonical `ControllerPlanReviewInput` preserved as dataset input.
- Exact canonical `ControllerPlanReviewResult` preserved as accepted output.
- Existing Plan-review prompt/schema/parser/bounds remain unchanged.
- Existing Plan-review persistence/authorization/workflow semantics remain unchanged.

## Non-goals

- Automatic curation from persisted Plan review or downstream workflow outcomes.
- Plan revision or memory-judgment curation yet.
- Generic curation framework.
- Dataset export/trainer formats.
- Dataset deduplication/ranking/sampling/balancing/splitting.
- Fine-tuning/evaluation runner changes.
- Runtime memory changes.

## Acceptance criteria

1. One explicit application API persists one verified Controller Plan-review interaction as one M08-001 example.
2. Capability identity is fixed as `controller.plan_review` and not caller-controlled.
3. Dataset input is the exact validated `ControllerPlanReviewInput` projection.
4. Dataset accepted output is the exact validated `ControllerPlanReviewResult` projection.
5. Observed and accepted values use the existing production Plan-review validation contract.
6. Equal outputs create non-correction examples; differing outputs require explicit corrected outcome and exact observed-output correction metadata.
7. Invalid/mismatched/unbounded data creates zero rows.
8. Successful curation creates exactly one row through M08-001 only.
9. No Plan-review inference/persistence/workflow behavior changes and no automatic harvesting/verification is introduced.
