# M01-002 — Integrate llama.cpp behind the local runtime boundary

**Status:** Done
**Milestone:** M01 — Native model runtime

## Objective

Implement the first real native `LocalInferenceRuntime` adapter using llama.cpp/GGUF and prove it with an opt-in local smoke test against a Qwen3 8B GGUF, without leaking backend-specific details across the M01-001 boundary.

## Why

M01-001 established the replaceable inference seam. M01 now needs one real local backend so Orc can execute bounded inference before M02 introduces Controller state and recommendations.

## Scope

- Inspect current Rust/native build conventions and current upstream llama.cpp integration options before choosing the concrete binding/linking mechanism.
- Integrate llama.cpp as a pinned/reproducible native dependency or adapter implementation behind `LocalInferenceRuntime`.
- Keep llama.cpp, GGUF, tokenizer/chat-template and model-loading details inside the adapter.
- Map `LocalRuntimeConfig` and bounded inference requests into backend configuration without expanding domain-facing types for llama.cpp-specific knobs.
- Support plain text completion required by the existing runtime response; structured output may use the existing generic response shape but must not require Controller schemas yet.
- Return existing typed runtime errors for unavailable backend, invalid configuration, model-load/inference failure and cancellation where applicable.
- Add deterministic adapter-boundary tests that require neither model weights nor network access.
- Add an explicitly opt-in real-model smoke path using a user-supplied GGUF path. It must not download or commit model weights.
- Document exact local smoke-test setup for Qwen3 8B GGUF.

## Integration constraints

- Prefer a direct native Rust/C/C++ integration over a long-lived HTTP/service dependency unless repository evidence shows that direct linking is materially worse. Record the reason if a subprocess/server boundary is chosen.
- Pin the llama.cpp integration sufficiently to avoid silently changing the native API underneath Orc.
- Do not add Python to Orc build/runtime/test paths.
- Normal deterministic tests and normal builds must not require a model file or network access.
- Do not expose raw llama.cpp handles or backend-specific configuration through `LocalInferenceRuntime`.

## Non-goals

- Do not build `ControllerStatePacket`.
- Do not connect inference to task lifecycle, database mutation, recovery, planning or Lead.
- Do not add memory.
- Do not add model downloading/updating infrastructure.
- Do not bundle model weights.
- Do not optimize GPU/backend packaging beyond what is required to prove the adapter on the current development platform.
- Do not fine-tune or convert models.

## Dependencies

- M01-001.

## Acceptance criteria

1. A real llama.cpp-backed implementation of `LocalInferenceRuntime` exists behind the M01-001 model-independent interface.
2. Qwen/GGUF/llama.cpp-specific types and settings remain internal to the adapter/build integration.
3. The native dependency is pinned/reproducible and does not introduce Python into Orc build/runtime/tests.
4. Normal deterministic tests require no network or model weights.
5. Backend/model-load/inference failures are translated into the existing typed local-runtime error surface rather than leaking native errors through domain-facing APIs.
6. An opt-in smoke test or small test harness can load a user-supplied Qwen3 8B GGUF and obtain a bounded local inference response.
7. The smoke path is documented with exact invocation/configuration and is excluded from normal deterministic test runs.
8. No lifecycle/database mutation or Controller state integration is introduced.

## Required tests/evidence

- Focused unit/integration tests for adapter configuration/error translation that run without model weights.
- `cargo fmt --check`.
- Focused Rust tests for `local_runtime` and the native adapter.
- `git diff --check`.
- One recorded opt-in real-model smoke result using a Qwen3 8B GGUF on the development machine, including model file identity, invocation, response success/failure and relevant runtime configuration. Do not commit the model.

## Result

Implemented with the exact-pinned `llama-cpp-2 = 0.1.155` binding behind the
optional `llama-cpp` Cargo feature. This is a direct native Rust/C++ integration:
the binding builds the pinned llama.cpp source locally, so there is no HTTP
service, Python runtime, model downloader or committed weight. `LlamaCppRuntime`
loads a user-supplied model once, creates a bounded context per request, maps
the generic context/thread/sampling/stop settings, and returns plain text or a
typed `LocalInferenceError`. Raw model/context/sampler handles, GGUF and
tokenizer details remain private to `src/local_runtime/llama_cpp.rs`.

Deterministic adapter tests cover missing-model error translation, generic
context/thread mapping and stop-sequence truncation. The real smoke test is
ignored, feature-gated and requires an explicit model path:

Install a C++ compiler, CMake and libclang for the pinned native binding, then
place a Qwen3 8B GGUF on disk yourself (the repository never downloads it):

```text
ORC_QWEN3_GGUF=/absolute/path/to/Qwen3-8B-Q4_K_M.gguf \
  cargo test --features llama-cpp --test local_runtime_smoke -- --ignored --nocapture
```

Record the local model identity when running the smoke with
`sha256sum "$ORC_QWEN3_GGUF"`; the adapter uses the 8192-token context,
unspecified thread count, greedy sampling and 64-token output bound shown in
the test.

It does not download or record model weights. Source review: **PASS**.

The opt-in real-model smoke passed using `Qwen3-8B-Q4_K_M.gguf`:

```text
ORC_QWEN3_GGUF=~/models/qwen3/Qwen3-8B-Q4_K_M.gguf cargo test --features llama-cpp --test local_runtime_smoke -- --ignored --nocapture
```

Result: `1 passed; 0 failed`, completed in `15.26s`. This proved the runtime
path end-to-end through `LocalInferenceRuntime` → `LlamaCppRuntime` →
llama.cpp → Qwen3 8B GGUF. The smoke execution was CPU-backed; Vulkan/GPU
optimization is separate and is not part of M01-002.

Focused default tests and the feature-gated native adapter tests pass with the
native prerequisites installed (`cargo test --features llama-cpp local_runtime`).
The pinned dependency and adapter source remain opt-in and do not affect
default builds.
