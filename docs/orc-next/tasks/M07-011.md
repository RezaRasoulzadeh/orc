# M07-011 — Compose one selected Controller memory maintenance step

**Status:** Done
**Milestone:** M07 — Supervised autonomy

## Objective

Compose the new M07-010 bounded maintenance-target selection with the existing M07-009 one-target maintenance chain into one explicit supervised operation that may select at most one current-project Project/Episodic target from caller-supplied current facts and then perform at most one canonical maintenance mutation under an existing finite M07-008 grant.

## Result

Implemented and independently reviewed **PASS**.

Canonical application API:

`OrcApp::maintain_selected_controller_memory_once(...)`

Production composition remains:

1. one M07-010 target-selection call;
2. `NoTarget` stops immediately, or the exact selected canonical `MemoryId` is carried forward;
3. one fresh `ControllerMemoryMaintenanceRequest` is constructed with that exact target and an unchanged clone of the caller-supplied `current_facts`;
4. one existing M07-009 `maintain_controller_memory_once(...)` call performs fresh M06-011 target resolution/judgment and, when applicable, M06-009 proposal → M07-008 grant → M06-009 execution.

The composition carries only `MemoryId`, never a cached `MemoryRecord`, across the selection-to-maintenance boundary. The selected target is therefore freshly re-resolved before authorization/mutation.

Public outcomes are state-safe and distinguish `NoTarget`, selected target kept, selected target mutated, selection rejection/failure, and post-selection maintenance rejection/failure. Selected-target/result pairing is enforced by private fields and crate-local constructors, and M07-009 successful mutation wrappers are reused rather than raw execution outcomes.

Per call the implementation permits at most one selection inference, one maintenance inference, one proposal, one authorization mint, one execution attempt, and one durable mutation. There is no retry, second selection, alternate target, omitted-candidate fallback, direct mutation, grant refund, or second orchestration loop.

Grant accounting remains entirely delegated to M07-009/M07-008: `NoTarget`, selection failures, Keep, and pre-mint maintenance failures consume zero; successful authorization consumes one; post-mint failure is not refunded.

Neither M07-010 nor M06-011 inference contracts changed, so no additional real-Qwen evaluation was required.

## Architectural conclusion

M07 now contains the intended bounded supervised-autonomy seams: finite routine task continuation, supervised project-bound memory Create, explicit-target maintenance, bounded Controller target selection, and one selected-target maintenance composition. Automatic workflow-derived memory facts/candidates remain intentionally excluded because deriving what should be remembered or what evidence warrants maintenance is judgment, not a kernel invariant.
