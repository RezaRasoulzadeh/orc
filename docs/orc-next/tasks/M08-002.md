# M08-002 — Add explicit typed curation for normal Controller recommendations

**Status:** Done
**Milestone:** M08 — Experience dataset

## Objective

Add the smallest capability-local adapter that converts one already-produced normal Controller recommendation interaction into one canonical M08-001 experience-example draft under explicit trusted verification metadata.

This task makes M08 usable for one real Controller reasoning surface without introducing automatic harvesting, automatic verification, or generic untyped JSON assembly.

## Repository-grounded context

M08-001 established the global typed `ControllerExperienceExampleDraft`/record substrate and explicit trusted persistence APIs.

Normal task recommendation already has canonical typed inference data:

- `ControllerRecommendationInput` — authoritative bounded current packet plus bounded memory context;
- `ControllerRecommendation` — parsed/validated advisory result produced by the existing normal recommendation path.

The next smallest seam is a capability-local deterministic projection from those existing typed values into one M08 draft. This preserves the production schema as dataset evidence while leaving verification judgment explicit and caller-owned.

## Scope

Add one capability-specific typed curation request/builder and the smallest `OrcApp` API needed to persist one explicitly verified normal Controller recommendation example.

The adapter must accept, at minimum:

- one existing validated `ControllerRecommendationInput`;
- one existing `ControllerRecommendation` representing the observed Controller output;
- one explicit accepted/expected recommendation result for the curated example;
- explicit M08-001 verification basis;
- explicit quality/outcome metadata;
- optional operator-correction metadata when accepted output differs from observed output;
- optional provenance fields supported by M08-001.

Do not infer verification, correction, quality, provenance, or acceptance from runtime/workflow state.

## Canonical projection

The dataset `capability` must be one fixed canonical identifier for normal task recommendation, owned by code rather than caller text.

The dataset `input` must be deterministically serialized from the exact typed `ControllerRecommendationInput` supplied to the adapter. Do not rebuild a parallel input schema.

The dataset accepted/expected output must be deterministically projected from the exact canonical structured recommendation decision used by the normal Controller schema. Do not train on arbitrary prose or introduce a second recommendation-output schema.

If the observed output differs from the accepted output, preserve the observed canonical output in M08-001 correction metadata and require the corrected M08 outcome/verification semantics to be internally consistent.

Do not silently normalize, summarize, reorder, truncate, or invent fields.

## Validation

Before M08 persistence, deterministically verify:

- the `ControllerRecommendationInput` passes its existing canonical validation;
- observed and accepted recommendation values are structurally valid for the existing normal Controller recommendation contract;
- task identity in recommendation data is consistent with the input task identity;
- accepted output is representable by the existing production recommendation schema;
- correction metadata exists iff the curated accepted output differs from observed output as required by M08-001 semantics;
- verification/outcome/quality/provenance are valid under M08-001;
- projected payloads fit M08-001 bounds without truncation.

Reuse existing production validation where possible. Do not duplicate recommendation legality or invent alternate schema rules.

## Persistence

On success, construct exactly one canonical `ControllerExperienceExampleDraft` and persist it only through existing `OrcApp::create_controller_experience_example(...)` / canonical storage path.

At most one dataset row may be created per call.

If any validation/projection fails, create no row.

## Invariants / requirements

- One capability only: normal task recommendation.
- Explicit trusted call only.
- No Controller inference.
- No automatic capture/harvesting.
- No workflow/task/review/validation/acceptance hook.
- No inference from execution success/failure.
- No generic caller-controlled capability string.
- No parallel recommendation input/output schema.
- Production recommendation behavior/prompt/schema remains unchanged.
- Runtime `MemoryKind::Experience` remains unchanged.
- M08-001 remains the sole persistence record format.
- No provider/model-specific behavior, embeddings, Python, export, splitting, balancing, or training.

## Non-goals

- Capturing every recommendation automatically.
- Capturing planning/recovery/intake/Plan review/Plan revision/memory judgments yet.
- Deriving labels from action execution, review, validation, acceptance, or workflow state.
- Dataset deduplication/ranking/sampling.
- Train/eval/test splitting.
- JSONL/trainer export.
- Fine-tuning.
- Runtime memory changes.

## Acceptance criteria

1. One explicit application API can persist one verified normal Controller recommendation as one M08-001 example.
2. Capability identity is fixed deterministically by the adapter.
3. Input is derived from the exact canonical `ControllerRecommendationInput`.
4. Accepted output is derived from the existing canonical structured recommendation schema, not arbitrary prose.
5. Observed-vs-accepted correction is explicit and internally consistent.
6. Invalid/mismatched/unbounded inputs or outputs write no dataset row.
7. At most one M08 row is created per call through the canonical M08-001 creation path.
8. No inference, automatic harvesting, workflow hook, label inference, memory change, or recommendation-contract change occurs.
