# M05-005 — Persist Controller Plan review decisions through explicit authorization

**Status:** Done
**Milestone:** M05 — Planning and Lead unification

## Objective

Connect validated M05-004 Controller Plan review results to canonical durable Plan review/status state through explicit trusted one-shot authorization without fabricating legacy Lead lineage.

## Result

Implemented truthful `PlanReviewOrigin`, `PlanReviewProvenance`, and typed `PlanReviewDecision`, plus a backward-compatible schema migration preserving legacy lineage, supersession, and foreign-key integrity.

Added typed `ControllerPlanReviewPersistenceProposal`, opaque one-shot authorization, bounded execution results, and `OrcApp` proposal/authorization/execution APIs. Execution freshly reloads and validates the current Controller-origin Plan before canonical persistence and reuses shared `record_plan_review_tx` for deterministic status transitions.

Legacy Lead review behavior and provenance remain intact. Successful Controller execution persists exactly one Controller-origin review and creates no Lead/Planner/task/workflow side effects.
