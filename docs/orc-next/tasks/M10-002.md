# M10-002 — Add TUI run history and worktree/diff inspection

**Status:** Planned
**Milestone:** M10 — Interface integration

## Objective

Make the Rust TUI sufficient for inspecting the execution history and code-change evidence behind a task without falling back to the CLI.

The operator should be able to move from a task to its canonical run history, inspect the selected run’s persisted evidence, and inspect the task worktree/change diff through existing Orc read and Git/review boundaries. This task is read-oriented: it improves operational understanding without adding new lifecycle mutation.

## Repository-grounded context

`docs/orc-next/M10-interface-audit.md` identified run/history and worktree/diff inspection as the next TUI adapter gaps after the normal lifecycle slice. The audit found that run listing/detail, lifecycle evidence, worker output/log evidence, worktree metadata, and review/change evidence already exist elsewhere in Orc. M10-001 completed the normal TUI lifecycle at `8106d75695da31dc5212b236eeeca60040e168b8`, including canonical creation, dispatch/review/revision/accept actions and manual refresh.

This task should expose existing evidence rather than create another run model, Git abstraction, or review representation. General recovery mutation, dependency mutation, explicit agent selection, Controller actions, M08 curation, and task metadata editing remain separate follow-on work.

## Dependencies

- M10-001 complete.
- `docs/orc-next/M10-interface-audit.md` present and reviewed.
- M09-007 may remain blocked; this task does not depend on specialization source data, training, or model selection.

## Scope

### Run history

Add a TUI run-history surface reachable from a selected task.

Use existing canonical run/read APIs to list persisted runs associated with the task. The list must expose enough canonical identity and state to distinguish attempts, including run ID, action/class where already represented, agent identity where available, persisted status, and relevant timestamps/economy/token summaries where already present in the shared model.

Do not infer or manufacture run states in TUI code.

### Run detail and evidence

Allow the operator to select a run and inspect the canonical evidence already persisted for it.

Present the bounded evidence that already exists through shared application/read boundaries, such as run identity/status, agent/action information, lifecycle/failure information, worker result/output or bounded log evidence where exposed, validation evidence, review/change evidence, and token/economy/context information already present in the run/read model.

The TUI must not read provider state directly or reconstruct canonical outcomes from raw output.

### Worktree inspection

Expose the selected task’s canonical worktree path/state when one exists.

Use the existing validated task-worktree/Git boundary. Do not trust an arbitrary stored path as a filesystem capability and do not add direct unvalidated filesystem traversal from TUI state.

The surface is informational only in this task. Do not add shell execution, file editing, worktree deletion, or mutation controls.

### Diff inspection

Provide a bounded TUI diff/change view for the selected task using existing Orc Git/review evidence paths.

The operator must be able to inspect the actual current task changes sufficiently to understand what the implementation changed. Preserve canonical worktree validation and existing change-evidence semantics.

The TUI must not implement a second Git diff parser, review engine, or change-classification policy when an existing canonical representation is available.

### Navigation and refresh

Integrate the new surfaces with the existing M10-001 queue/detail navigation.

Support predictable keyboard navigation between task detail, run list, run detail, worktree/diff view, and back navigation. Manual refresh must re-read canonical state and preserve selection where safely possible.

Errors, missing worktrees, absent runs, stale/deleted worktrees, and unavailable evidence must be represented explicitly without crashing or silently fabricating empty success states.

- No new Git/worktree ownership model, diff parser, review engine, validation execution, or run-state inference.
- No general task metadata editor.
- No Controller recommendation/authorization/execution UI.

## Acceptance criteria

1. From TUI task detail, the operator can open the selected task’s persisted run history without using the CLI.
2. Run history uses canonical run/read data and distinguishes persisted attempts without TUI-local state inference.
3. A selected run exposes the relevant canonical run, failure/lifecycle, validation, review/change, and token/economy evidence that is already available through shared APIs.
4. The TUI can show the task’s validated canonical worktree identity/path when present and handles missing/stale/invalid worktree state safely.
5. The operator can inspect the selected task’s actual current diff/change evidence through existing Git/review boundaries without a duplicate diff/review implementation.
6. Manual refresh re-reads canonical state for the new views and does not silently preserve stale evidence as current.
7. Empty history, missing evidence, missing worktree, invalid worktree, and application/read failures are bounded and visible to the operator.
8. The implementation does not add lifecycle mutation, recovery mutation, scheduler logic, direct database writes, or unsafe filesystem access.
9. No M09 behavior/state, Controller inference, model default, promotion gate, or M08 supervised-curation authority changes.

## Required review

The reviewer must verify that the TUI delegates run history/detail, worktree validation, and diff/change evidence to existing canonical Rust boundaries and does not reconstruct authoritative state from provider output or raw filesystem assumptions.

Review-stage validation should include focused TUI tests for navigation/state and integration coverage that creates or uses a task with multiple persisted runs and real worktree changes, then verifies run-list/detail refresh plus worktree/diff inspection. Include missing/invalid worktree and empty-history/error behavior. Run the smallest relevant application/Git/read-model regression set, `cargo fmt --check`, clippy for affected supported feature sets, and `git diff --check`.

Execution/revision agents should not spend separate turns running the completed review validation suite.
