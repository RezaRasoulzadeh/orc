# M07-010 — Add bounded Controller memory maintenance target selection

**Status:** Done
**Milestone:** M07 — Supervised autonomy

## Objective

Add the smallest read-only Controller judgment needed to choose whether one active current-project Project/Episodic memory record should be considered for maintenance from a deterministic bounded candidate set and explicit current facts.

This task selects at most one target or no target. It does not invoke M06-011 maintenance judgment, mint authorization, mutate memory, scan in the background, or attach maintenance to workflow events.

## Repository-grounded context

M07-009 proves the complete supervised maintenance chain once a caller supplies one explicit `ControllerMemoryMaintenanceRequest`. The remaining judgment before safe automatic-capable maintenance is target selection.

`MemoryService::list(...)` already provides canonical current-project memory enumeration. M06-011 already owns the separate judgment of Keep versus Correct/Supersede/Remove for one resolved active target. M07-008/M07-009 own bounded permission and execution composition. Therefore target selection must remain a read-only capability and must not duplicate maintenance judgment or mutation legality.

## Scope

Add one capability-specific bounded input/result and the smallest `OrcApp` read-only API.

Required behavior:

- trusted application code supplies bounded explicit current facts relevant to deciding whether maintenance may be warranted;
- application deterministically enumerates only active exact-current-project `MemoryKind::Project` and `MemoryKind::Episodic` records through the canonical memory service;
- User, Experience, global, historical/corrected/superseded/removed, and cross-project records are excluded before inference;
- candidates are projected into bounded declarative data with stable `MemoryId`, kind, scope, subject/content, provenance/confidence/lifecycle/lineage only as needed for judgment; no storage handles;
- deterministic stable ordering and hard candidate/input byte bounds;
- if more legal candidates exist than fit the bound, deterministic truncation/omission is observable in trusted input metadata rather than hidden or model-chosen;
- exactly one Controller inference at most;
- result is exactly `NoTarget` or `SelectTarget { target: MemoryId }`;
- selected target must be one exact candidate from the supplied bounded input;
- malformed/unknown/retargeted/global/cross-project/historical output is rejected deterministically;
- current facts outrank historical/advisory memory content;
- target selection does not decide Correct/Supersede/Remove; M06-011 remains authoritative for maintenance action judgment;
- no grant is inspected or consumed;
- no mutation proposal, authorization, execution, or persistence occurs.

## Invariants / requirements

- Read-only capability only.
- At most one target selected.
- At most one inference.
- No automatic iteration over omitted candidates.
- No retry or second inference.
- No User/Experience/global target can enter the candidate set or result.
- No historical record can enter the candidate set or result.
- No cross-project target can enter the candidate set or result.
- Candidate identity is canonical and cannot be rewritten by the model.
- Deterministic code owns enumeration, filtering, ordering, bounds, and result validation; Controller owns whether any bounded candidate appears worth maintenance.
- M06-011 prompt/schema/behavior remains unchanged.
- M06-009 and M07-008/M07-009 remain unchanged.
- No provider token hard cap, Python, or model-specific behavior.

## Non-goals

- Invoking `maintain_controller_memory_once(...)` automatically.
- Choosing Correct/Supersede/Remove during selection.
- Automatically deriving current facts from workflow/task/Plan/review/validation/recovery/transcript events.
- Workflow/lifecycle hooks.
- Background or periodic scans.
- Repeated/batch target selection.
- Automatic capture candidate derivation.
- User/Experience maintenance.
- Semantic/vector retrieval, embeddings, or learned ranking.
- Grant changes or persistence.
- CLI/TUI/GUI integration.

## Acceptance criteria

1. One read-only `OrcApp` API builds a bounded deterministic candidate set from active current-project Project/Episodic records and performs at most one Controller inference.
2. Result is only no target or one exact candidate identity.
3. User/Experience/global/historical/cross-project records cannot be selected.
4. Candidate ordering/filtering/bounds are deterministic and truncation/omission is observable.
5. Invalid or invented target identities are rejected.
6. No M06-011 judgment, grant consumption, proposal, authorization, mutation, persistence, retry, or workflow hook occurs.
7. Existing memory, M06-011, M07-008, and M07-009 behavior remains unchanged.

## Completion evidence

Implemented as `OrcApp::select_controller_memory_target(...)` with capability-specific selection request/input/candidate/result types. Production bounds are 16 facts, 2048 bytes per fact, 8 candidates, 8192 bytes per candidate, 32768-byte serialized input, 49152-byte prompt, 4096-byte structured result, and 256 output tokens. Candidate enumeration is canonical and deterministic, limited to active exact-current-project Project/Episodic records, with deterministic Project/Episodic → creation-time → ID ordering and observable eligible/selected/omitted counts. Oversized/excess candidates are omitted without UTF-8 truncation, and result validation binds any selected target to the exact bounded candidate set supplied to inference.

Independent Luna/High review passed. Focused selector tests, relevant M06/M07 regressions, normal and llama-cpp library tests, both clippy modes, formatting, and diff checks passed. Focused real-Qwen evaluation passed strict structured output 7/7 and semantic target selection 7/7 with no failures. No existing inference contract changed.
