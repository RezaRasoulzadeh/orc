# CLI reference

This is the complete command surface for the `orc` binary (v0.3.0). Every top-level command and subcommand is listed with its arguments, flags, and behavior. Run `orc --help` or `orc <command> --help` for the same information from the binary itself.

Conventions used below:
- `TASK_ID` refers to a task identifier such as `T-0001`.
- `RUN_ID` refers to an integer run identifier.
- Arguments in `UPPERCASE` are positional and required unless noted otherwise.
- `--flag <VALUE>` flags are optional unless noted otherwise.
- Where a command accepts a file path and documents stdin support, pass `-` to read from stdin instead of a file.

Planning, review, and Lead responses generated by automated actions are read-only until a human explicitly validates/applies (`apply-plan`, `apply-response`) or resolves the result (`approvals resolve`). Review never accepts or merges work on its own — `task accept` does. Malformed structured input (bad protocol version, invalid plan/response JSON) fails validation without mutating any state.

### Archive and purge semantics

`orc agent remove ID` is a soft archive. `orc agent purge ID` is irreversible, clears any Lead provider reference, removes the registered agent and action profiles, and preserves historical run attribution. It is refused while the agent owns a running or waiting-external run.

Task cancellation is also retained history. `orc task purge TASK_ID` is irreversible. Without `--force`, the task must be done or cancelled, have no dependents, and have a clean canonical worktree. `--force` bypasses terminal and dependent-task restrictions and removes dependency edges and the worktree, but never bypasses active/waiting-run protection or unsafe worktree-path checks.

### `orc --ui`
Launches the installed desktop application and returns immediately. Cannot be combined with any other command.

## Project and health

### `orc init`
Bootstraps Orc local state by initializing the SQLite database at `.orc/orc.db` in the current directory and creating the project record if one does not already exist. It does not require Git and does not itself adopt a repository. Safe to run repeatedly; existing project documents and the engineering contract are preserved.

### `orc adopt`
Brings the existing Git repository in the current directory under Orc management. It requires a Git repository, initializes local Orc state if needed, creates missing project documents, and preserves every existing project document, including `.orc/engineering.md`. Adoption is idempotent. It does not install Orc or modify source files.

### `orc discovery-request`
Emits a read-only repository discovery request as JSON to stdout. This request is meant to be handed to a planner/agent that inspects the repository and returns a structured discovery response — the command itself does not scan the repository or mutate state.

### `orc apply-discovery PATH`
Applies a structured repository discovery response from a JSON file (or `-` for stdin) to project state (architecture, modules, boundaries facts used later in `orc report --full`).
- `PATH` — path to the discovery response JSON file, or `-` for stdin.

### `orc doctor`
Diagnoses project and configured-agent health without consuming any model quota. Checks include repository adoption state, database presence, and agent CLI availability. Prints a pass/fail status per check.

### `orc status`
Prints the project name and a one-line summary (ID, status, title) for every task in the database. Prints a helpful message instead if no DB or project exists yet.

### `orc report [--full]`
Emits a structured `ProjectReport` JSON document to stdout, intended for a manual/external planner.
- `--full` — include architecture facts (modules, boundaries, and raw discovery data) captured by a prior `orc apply-discovery`. Without this flag, architecture fields are empty.

## Planning and the Engineering Lead

### `orc plan-request OBJECTIVE [--full-report]`
Emits a read-only `PlanningRequest` JSON document to stdout for a given objective, including the engineering contract, current project state, and (optionally) a full project report.
- `OBJECTIVE` — free-text description of the high-level goal to plan for.
- `--full-report` — embed a full `ProjectReport` (equivalent to `orc report --full`) inside the planning request.

### `orc apply-plan PATH`
Validates and atomically applies a structured `PlanResponse` JSON document, creating the tasks and dependencies it describes. Warns (without failing) if a task declares a context file that does not exist on disk. Fails without mutating state if the response is invalid.
- `PATH` — path to the plan response JSON file, or `-` for stdin.

### `orc plan OBJECTIVE [--agent AGENT] [--model MODEL] [--effort EFFORT]`
Runs an automated planning action: builds a planning request for `OBJECTIVE` and dispatches it to a supported automated agent, printing the resulting `PlanResponse` JSON. This does not apply the plan — review it and run `orc apply-plan` to persist it.
- `OBJECTIVE` — free-text description of the high-level goal to plan for.
- `--agent AGENT` — explicit agent ID to use instead of the deterministically selected one.
- `--model MODEL` — override the model for this run (automated Codex agents only).
- `--effort EFFORT` — override reasoning effort for this run: `none`, `low`, `medium`, or `high` (automated Codex agents only).

### `orc ask REQUEST [--agent AGENT] [--model MODEL] [--effort EFFORT]`
Emits an `EngineeringLeadRequest` for a free-text request, addressed to the configured Lead. With a supported automated Lead agent, this also dispatches the request and prints the resulting `EngineeringLeadResponse`.
- `REQUEST` — free-text description of what to ask the Engineering Lead.
- `--agent AGENT` — explicit agent ID to use instead of the configured Lead.
- `--model MODEL` — override the model for this run (automated Codex agents only).
- `--effort EFFORT` — override reasoning effort for this run (automated Codex agents only).

### `orc apply-response PATH`
Validates and persists an `EngineeringLeadResponse` JSON document (for example, one produced manually in response to `orc ask`).
- `PATH` — path to the response JSON file, or `-` for stdin.

### `orc lead show`
Prints the currently configured Engineering Lead agent, if any.

### `orc lead set AGENT [--model MODEL] [--effort EFFORT]`
Configures the Engineering Lead agent.
- `AGENT` — agent ID to use as the Engineering Lead.
- `--model MODEL` — model override for Lead actions (automated Codex agents only).
- `--effort EFFORT` — reasoning effort override for Lead actions (automated Codex agents only).

### `orc lead clear`
Clears the configured Engineering Lead.

## Tasks

### `orc task create TITLE OBJECTIVE [options]`
Creates one task directly in the current project.
- `TITLE` — short task title.
- `OBJECTIVE` — task objective/description.
- `--role ROLE` — role for the task (default: `developer`).
- `--priority PRIORITY` — one of `low`, `normal`, `high`, `critical` (default: `normal`).
- `--capability CAP` — required capability; comma-delimited, repeatable.
- `--scope SCOPE` — scope mode for the task's worktree (see `orc task scope`).
- `--context PATH` — context file path(s) to attach; comma-delimited, repeatable.
- `--expect PATH` — expected-change path(s); comma-delimited, repeatable.
- `--depends-on TASK_ID` — dependency task ID(s); comma-delimited, repeatable.

### `orc task list`
Lists all tasks as `ID  STATUS  TITLE`.

### `orc task show TASK_ID`
Prints full task detail: ID, title, objective, role, priority, status, cancellation reason (if any), required capabilities, scope mode, context files, expected changes, and dependencies.

### `orc task require TASK_ID CAPABILITY [CAPABILITY...]`
Sets (replaces) the required capabilities for a task.
- `TASK_ID` — task to configure.
- `CAPABILITY...` — one or more required capabilities (e.g. `code`, `terminal`, `architecture review`).

### `orc task scope TASK_ID MODE`
Sets the scope mode for a task's worktree.
- `TASK_ID` — task to configure.
- `MODE` — scope mode string (see `docs/concepts` for valid scope modes).

### `orc task context-add TASK_ID PATH [PATH...]`
Adds one or more context file paths to a task.

### `orc task context-clear TASK_ID`
Clears all context file paths from a task.

### `orc task expect-change TASK_ID PATH [PATH...]`
Adds one or more expected-change paths to a task.

### `orc task expect-clear TASK_ID`
Clears all expected-change paths from a task.

### `orc task diff TASK_ID`
Shows the unified diff for the task's worktree, if one exists.

### `orc task worktree TASK_ID`
Shows worktree metadata for a task: branch name and worktree path.

### `orc task accept TASK_ID`
Accepts a reviewed task: integrates its branch and marks the task done.

### `orc task reject TASK_ID [REASON]`
Rejects a reviewed task while preserving its worktree, returning it to ready.
- `REASON` — optional free-text rejection reason.

### `orc task cancel TASK_ID [REASON]`
Cancels a task while preserving its worktree. Fails if the task is already done or already cancelled.
- `REASON` — optional free-text cancellation reason.

### `orc task requeue TASK_ID`
Recovers an interrupted active task or a failed blocked task and returns it to the queue.

### `orc task purge TASK_ID [--force]`
Irreversibly deletes a task and its persisted state. Without `--force`, the task must be done or cancelled, have no dependents, and have a clean canonical worktree. `--force` bypasses terminal and dependent-task restrictions and removes dependency edges and the worktree, but never bypasses active/waiting-run protection or unsafe worktree-path checks.
- `TASK_ID` — task to purge.
- `--force` — bypass terminal-state and dependent-task restrictions.

### `orc task depend TASK_ID DEPENDENCY_ID`
Adds a dependency: `TASK_ID` now depends on `DEPENDENCY_ID`.

### `orc task undepend TASK_ID DEPENDENCY_ID`
Removes a previously added dependency.

## Queue and scheduling

### `orc queue [--explain]`
Shows the deterministic task queue.
- `--explain` — also print dependency state, readiness, and scheduler-eligibility explanations for each task.

### `orc schedule TASK_ID [--explain] [--mode MODE]`
Evaluates deterministic agent selection for a task without dispatching it.
- `TASK_ID` — task to schedule.
- `--explain` — print candidate evaluations and the reasoning behind the selection.
- `--mode MODE` — restrict candidate agents to `automated` or `manual`.

## Dispatch and runs

### `orc dispatch TASK_ID [--agent AGENT] [--model MODEL] [--effort EFFORT]`
Dispatches a task using a selected registered agent.
- `TASK_ID` — task to dispatch (e.g., `T-0001`).
- `--agent AGENT` — explicit agent override; selection-validity checks still apply.
- `--model MODEL` — model override for this run (automated Codex agents only).
- `--effort EFFORT` — reasoning-effort override for this run (automated Codex agents only).

### `orc dispatch-queue [--concurrency N]`
Dispatches all ready automated tasks concurrently.
- `--concurrency N` — maximum number of tasks to execute at once; a positive integer or `auto` (default: `1`).

### `orc runs [TASK_ID]`
Lists agent runs, optionally filtered to a single task.
- `TASK_ID` — optional task ID to filter runs for.

### `orc run submit RUN_ID [--file PATH]`
Submits output for a waiting manual run, moving its task to review.
- `RUN_ID` — the manual run to submit output for.
- `--file PATH` — read output from a file instead of stdin.

### `orc run submit-patch RUN_ID PATCH_FILE`
Submits a Git patch for a waiting manual run: applies and validates the patch in the run's worktree, printing the validation report and moving the task to review on success.
- `RUN_ID` — the manual run to submit a patch for.
- `PATCH_FILE` — path to the patch file, or `-` for stdin.

### `orc run fail RUN_ID [REASON]`
Marks a manual run as failed, moving its task to blocked.
- `REASON` — optional free-text failure reason (default: `manual run failed`).

## Review and revision

### `orc review TASK_ID [options]`
Reviews the latest run for a task and its worktree changes. Review never accepts or merges work; use `orc task accept` for that.
- `TASK_ID` — task to review.
- `--automated` — run an automated review action instead of only displaying the diff.
- `--agent AGENT` — agent override for the automated review (requires `--automated`).
- `--model MODEL` — model override for the automated review (requires `--automated`).
- `--effort EFFORT` — reasoning-effort override for the automated review (requires `--automated`).
- `--diff` — show the complete unified diff (conflicts with `--file`).
- `--file PATH` — show the unified diff for one changed file only (conflicts with `--diff`).
- Task-scoped automated review verifies the task contract; unrelated and pre-existing findings are non-blocking.

### `orc project-review TASK_ID [--agent AGENT] [--model MODEL] [--effort EFFORT]`
Runs an unrestricted project-wide automated audit using the task's captured evidence. It may report broader architecture, latent defects, technical debt, missing tests, and adjacent concerns.
- `TASK_ID` — task whose captured evidence seeds the audit.
- `--agent AGENT` — explicit agent override.
- `--model MODEL` — model override for this run (automated Codex agents only).
- `--effort EFFORT` — reasoning-effort override for this run (automated Codex agents only).

### `orc revise TASK_ID [FEEDBACK] [--agent AGENT] [--model MODEL] [--effort EFFORT]`
Revises a reviewed task using review feedback, redispatching it.
- `TASK_ID` — task to revise.
- `FEEDBACK` — optional free-text feedback to send back to the worker; when omitted, the persisted review contract is used.
- `--agent AGENT` — explicit agent override for the revision run.
- `--model MODEL` — model override for an automated revision run.
- `--effort EFFORT` — reasoning-effort override for an automated revision run (`none`, `low`, `medium`, or `high`).

## Agents

### `orc agents [--sync]`
Lists registered agents (`ID  STATUS`).
- `--sync` — synchronize quota for enabled, supported agents before listing.

### `orc agent list`
Lists registered agents (`ID  STATUS`) — equivalent to `orc agents` without `--sync`.

### `orc agent add ID --backend BACKEND [options]`
Registers a new agent.
- `ID` — unique agent identifier.
- `--backend BACKEND` — one of `copilot`, `codex`, `antigravity`, `chatgpt`, `claude`, `generic_manual` (required). Automated mode additionally requires the backend to be `codex`, `copilot`, or `antigravity`.
- `--priority N` — selection priority (default: `0`).
- `--capability CAP` — a capability the agent provides; repeatable.
- `--action ACTION` — a supported action (`code`, `review`, `plan`, or `lead`); repeatable. Defaults to `code`.
- `--display-name NAME` — human-readable display name (default: the agent ID).
- `--profile PATH` — provider configuration profile directory.
- `--model MODEL` — model to use (automated Codex agents only).
- `--effort EFFORT` — reasoning effort: `none`, `low`, `medium`, `high` (automated Codex agents only).
- `--mode MODE` — `automated` or `manual` (default: `automated`).

### `orc agent onboard ID --backend BACKEND [options]`
Inspects and optionally registers a globally reusable agent. Provider login is checked without making an AI request; discovered provider capabilities, operator permissions, and Orc roles are displayed separately.
- `--approve` — explicitly approve the inspection and persist the configuration. Without it, onboarding is preview-only.
- `--permission PERMISSION` — operator-granted access (`repository-read`, `repository-write`, `command-execution`, or `network-access`); repeatable.
- `--role ROLE` — Orc role assignment (`code`, `review`, `plan`, or `lead`); repeatable. `--action` is accepted as an alias.
- The remaining provider/configuration flags match `orc agent add`.

### `orc agent export ID [--output PATH]`, `orc agent import PATH`, and `orc agent update ID PATH`
Export or validate a versioned global agent configuration. Imports and updates are atomic and reject unsupported configuration/model versions, non-global agents, invalid provider configuration, and unverified authentication evidence. Provider credentials are never exported.

### `orc agent permissions ID`, `orc agent permission-add ID PERMISSION`, and `orc agent permission-remove ID PERMISSION`
Inspect or change operator-granted permissions. These permissions are persisted independently from provider capabilities and Orc role assignments.

### `orc agent enable ID`
Enables a previously registered agent.

### `orc agent disable ID`
Disables an agent without removing it.

### `orc agent remove ID`
Archives (soft-removes) an agent.

### `orc agent purge ID`
Irreversibly removes a registered agent: clears any Lead provider reference, removes the agent and its action profiles, and preserves historical run attribution. Refused while the agent owns a running or waiting-external run.
- `ID` — agent to purge.

### `orc agent available ID`
Marks an agent as available for selection.

### `orc agent unavailable ID REASON`
Marks an agent as unavailable, recording a reason.
- `REASON` — free-text reason the agent is unavailable.

### `orc agent priority ID PRIORITY`
Sets an agent's selection priority.
- `PRIORITY` — integer priority value.

### `orc agent profile ID PATH`
Sets the configuration profile directory for an existing agent.

### `orc agent model ID MODEL`
Sets the model for an agent (automated Codex agents only).

### `orc agent effort ID EFFORT`
Sets the reasoning effort for an agent (automated Codex agents only).
- `EFFORT` — one of `none`, `low`, `medium`, `high`.

### `orc agent quota ID --remaining N [--reset TIMESTAMP]`
Manually sets an agent's quota state.
- `--remaining N` — remaining quota percent, `0`–`100` (required).
- `--reset TIMESTAMP` — optional quota reset time.

### `orc agent quota-clear ID`
Clears manually set quota state for an agent.

### `orc agent quota-reserve REMAINING`
Sets the global automatic-dispatch quota reserve.
- `REMAINING` — reserved percent, `0`–`100`.

### `orc agent sync ID`
Synchronizes an agent's quota through the provider's machine-readable protocol and prints the resulting quota snapshot.

### `orc agent show ID`
Prints full agent detail: ID, backend, execution mode, model, reasoning effort, display name, enabled state, availability, unavailable reason, priority, quota (remaining/reset/checked/source and effective/primary/secondary/individual limits when known), capabilities, supported actions, and profile path.

### `orc agent actions ID`
Shows each supported action and its configured model and reasoning-effort profile.

### `orc agent action-add ID ACTION`
Adds one supported action. `ACTION` is `code`, `review`, `plan`, or `lead`.

### `orc agent action-remove ID ACTION`
Removes one supported action. The final supported action cannot be removed.

## Execution templates

Persistent per-class execution templates (model and reasoning effort) for `coder`, `reviewer`, `architect`, `researcher`, and `general` classes.

### `orc template list`
Lists the current model/effort template for every execution class.

### `orc template set CLASS [--model MODEL] [--effort EFFORT]`
Sets the persistent template for an execution class. At least one of `--model` or `--effort` must be given.
- `CLASS` — one of `coder`, `reviewer`, `architect`, `researcher`, `general`.
- `--model MODEL` — model to persist for this class.
- `--effort EFFORT` — reasoning effort to persist for this class.

### `orc template clear CLASS`
Clears the persistent template for an execution class.

## Approvals

### `orc approvals list`
Lists unresolved approval requests for the current project (`ID  REASON`).

### `orc approvals resolve ID`
Resolves an approval request.
- `ID` — integer approval request ID.
