# M06-009 — Establish supervised Controller memory mutation boundary

**Status:** Done
**Milestone:** M06 — Persistent memory

## Objective

Establish the smallest safe boundary through which Controller judgment can propose durable memory changes while the deterministic kernel retains validation, authorization, scope enforcement, lifecycle invariants, and canonical mutation.

This is the prerequisite for later Controller memory capture/consolidation. Do not add autonomous memory writing or consolidation inference in this task.

## Repository-grounded context

M06-001 already provides canonical typed memory storage and `MemoryService` operations for create/get/list/correct/supersede/remove/history across project and global persistence authorities. M06-002 provides bounded read-only `ControllerMemoryContext`. M06-003 through M06-008 supply that context to the existing Controller judgment capabilities.

The repository already has the architectural pattern needed for safe mutation: `src/controller_actions.rs` separates typed Controller proposals from trusted one-shot authorization and canonical execution. Memory uses an equivalent narrow boundary rather than giving the model `MemoryService`, database, registry, filesystem, or mutation handles.

## Scope

Add a typed supervised memory-mutation boundary over the existing M06-001 APIs.

Required behavior:

- define bounded typed Controller memory mutation intents for create, correct, supersede, and remove;
- intents carry only bounded declarative memory data and stable target identity where required;
- deterministically validate kind/scope/project binding, payload/provenance/confidence bounds, target identity, lifecycle eligibility, and current project ownership before authorization/execution;
- introduce a trusted one-shot, non-serializable authorization minted by Orc/application code for exactly one validated memory intent;
- execution consumes authorization, revalidates against fresh canonical memory state, and performs mutation only through existing `MemoryService`/M06-001 storage APIs;
- stale, mismatched, replayed, cross-project, invalid-lifecycle, or otherwise illegal intents fail without mutation;
- preserve User/Experience global authority and Project/Episodic exact-project authority;
- return canonical typed mutation results for supervised callers;
- no local-model inference.

## Invariants / requirements

- Controller proposes; kernel authorizes and mutates.
- Reuse M06-001 memory types and operations; no second persistence or lifecycle model.
- Memory authorization remains distinct from task-action authorization.
- Authorization is opaque/non-serializable, scoped to one exact validated intent, and consumed on execution.
- Fresh canonical validation occurs at execution.
- No model-facing code receives `MemoryService`, `Database`, registry, filesystem, workflow, or arbitrary command access.
- Correction/supersession/removal lineage and history remain M06-001 authoritative.
- Project/global persistence routing remains unchanged.
- No automatic capture, consolidation/deduplication judgment, semantic/vector retrieval, embeddings, learned ranking, model-specific behavior, or Python.

## Acceptance criteria

1. Bounded typed memory mutation intents exist over canonical M06-001 create/correct/supersede/remove operations.
2. Deterministic legality validates scope, project binding, target identity/current lifecycle, payload metadata and current ownership before mutation.
3. Trusted Orc code can mint an opaque one-shot authorization for exactly one validated intent.
4. Execution consumes authorization, revalidates fresh canonical state, and mutates only through existing M06-001 memory APIs.
5. Mismatched/replayed/stale/cross-project/invalid intents cannot mutate memory.
6. User/Experience global and Project/Episodic project-bound persistence authority is preserved.
7. Existing correction/supersession/removal history and lineage semantics remain canonical and transactional.
8. No inference, autonomous capture, consolidation, semantic retrieval, or unrelated workflow redesign is introduced.
