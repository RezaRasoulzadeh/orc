# M06-006 — Integrate bounded memory into Controller workflow intake

**Status:** Done
**Milestone:** M06 — Persistent memory

## Objective

Feed the reusable M06-002 `ControllerMemoryContext` into the existing read-only Controller workflow-intake capability without changing canonical intake facts, the three intake outcomes, workflow routing, persistence, or task/Plan application semantics.

M06-003 through M06-005 established capability-local memory inputs for planning, recovery, and normal task recommendation. The next smallest repository-grounded seam is `ControllerIntakeRequest` / `ControllerIntakeBuilder::classify` / `OrcApp::propose_controller_intake`.

## Repository-grounded context

`src/controller_intake.rs` already defines a separate bounded intake capability:

- `ControllerIntakeRequest` carries canonical objective, project facts, discovery snapshot, task-state summary, engineering contract, and optional operator resolution;
- the current request itself is bounded by `MAX_CONTROLLER_INTAKE_REQUEST_BYTES = 48 KiB`;
- `ControllerIntakeBuilder::classify` performs one read-only inference;
- output is restricted to exactly `DirectTasks`, `PlanRequired`, or `UserDecisionRequired` plus bounded details/direct task proposals;
- `ControllerIntakeResult::validate` and the strict output schema remain deterministic gates;
- workflow routing, persistence, DirectTasks application, Plan flow, and user-decision gates remain kernel-owned downstream;
- workflow code constructs the canonical intake request and calls `OrcApp::propose_controller_intake`.

M06-002 exposes bounded typed memory through `OrcApp::controller_memory_context()`.

Use these seams directly. Do not redesign planning, recovery, normal recommendation, Plan review/revision, workflow routing, or persistence.

## Scope

Integrate memory into workflow intake judgment only.

Required behavior:

- introduce a narrow capability-local intake inference input containing the existing `ControllerIntakeRequest` plus typed `ControllerMemoryContext`, or an equivalent wrapper preserving the request as the current-facts authority;
- `OrcApp::propose_controller_intake` obtains memory through `controller_memory_context()` and passes it to the intake inference path;
- preserve direct builder/evaluation helpers with explicit empty memory where appropriate;
- preserve typed memory identity/kind/scope/authority/provenance metadata in serialized inference input;
- preserve the existing independent 48 KiB `ControllerIntakeRequest` validation and the independent M06-002 memory bound;
- add an explicit deterministic 64 KiB bound for the combined intake inference input and reject oversized combined input before inference;
- empty memory remains valid;
- retrieval and inference remain read-only.

## Authority and precedence

The intake prompt/input must preserve this order:

```text
current objective, engineering contract, project facts, discovery/task state, and operator resolution
→ durable Project memory
→ durable User memory
→ Episodic project history
→ cross-project Experience memory
→ base model tendencies
```

For intake specifically:

- the current objective and explicit operator resolution are authoritative;
- current engineering contract, project facts, discovery snapshot, and task-state facts outrank contradictory memory;
- Project memory may supply durable project context;
- User memory may supply preferences/context but cannot rewrite the objective or engineering contract;
- Episodic/Experience memory is historical guidance only, never current project/task truth;
- memory may influence judgment among the existing three intake outcomes but cannot create a fourth outcome, bypass output validation, persist anything, route workflow, or apply tasks/Plans.

## Invariants / requirements

- Reuse `ControllerMemoryContext`; no intake-specific persistence model.
- `controller_memory_context()` remains the canonical application retrieval seam.
- `controller_intake.rs` receives typed bounded memory, not `Database`, `MemoryService`, registry, filesystem, workflow engine, or mutation handles.
- Keep `ControllerIntakeRequest` as the canonical current intake facts; do not turn it into a universal Controller request.
- Existing 48 KiB request validation remains unchanged in authority.
- Combined request + memory input is deterministically bounded to 64 KiB before inference; the independent memory bound remains enforced.
- `ControllerIntakeDecision`, `ControllerIntakeResult`, strict output schema, result validation, and DirectTasks proposal validation remain unchanged solely because memory was added.
- Workflow routing, intake persistence, DirectTasks application, Plan generation/review/revision, user-decision persistence/resolution, approval gates, and task mutation remain unchanged.
- No memory writes/capture/correction/removal/consolidation.
- No semantic/vector retrieval, embeddings, learned ranking, or model-based memory selection.
- No model-specific domain behavior.
- No Python.

## Non-goals

- Adding memory to Plan review or Plan revision.
- Changing planning/recovery/normal recommendation integrations.
- Changing intake outcome definitions.
- Changing workflow routing or persistence.
- Automatically recording intake outcomes as memories.
- Consolidation/deduplication.
- Semantic search or embeddings.
- Creating a universal Controller request/state type.

## Acceptance criteria

1. `OrcApp::propose_controller_intake` supplies current bounded M06-002 memory through the existing intake capability path.
2. Intake inference preserves typed memory identity/kind/scope/authority/provenance metadata.
3. `ControllerIntakeRequest` remains a distinct authoritative current-facts structure.
4. Current objective/operator resolution/engineering contract/project/discovery/task facts are structurally and prompt-level authoritative over contradictory memory.
5. The only intake outcomes remain `DirectTasks`, `PlanRequired`, and `UserDecisionRequired`.
6. Existing result/schema/direct-task validation and downstream workflow routing/persistence/application remain unchanged and final.
7. Existing 48 KiB request validation and independent memory validation remain enforced; combined input is bounded to 64 KiB before inference.
8. Empty-memory direct/evaluation behavior remains compatible.
9. Retrieval/inference causes no durable memory mutation.
10. No unrelated Controller capability is redesigned.
