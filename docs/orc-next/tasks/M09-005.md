# M09-005 — Investigate native/offline Controller specialization backend

**Status:** Done
**Milestone:** M09 — Controller specialization

## Objective

Investigate and recommend the smallest viable native/offline specialization path for the existing Qwen3 8B Controller, using repository evidence and current upstream capabilities, before implementing dataset transformation or training.

## Completed scope

Produced the repository-grounded investigation report at `docs/orc-next/M09-005-native-specialization-investigation.md`.

The investigation compared native llama.cpp training, ms-swift LoRA, LlamaFactory, and full fine-tuning; separated inference, adapter training, merging, conversion, quantization, and GGUF inference boundaries; verified Qwen3 checkpoint roles and artifact constraints; inspected repository/runtime boundaries; and measured the available local hardware/model/dataset state without mutation, downloads, or training.

Backend selection is explicitly deferred. The conditional first qualification path is isolated offline LoRA training with `ms-swift` using an explicitly selected original Qwen3 Hugging Face checkpoint, followed by adapter merge, pinned HF-to-GGUF conversion/quantization, existing M09-003 evaluation, and the fixed M09-004 comparison gate. This is not an Orc runtime dependency or authorization to train.

The report distinguishes `Qwen/Qwen3-8B` from `Qwen/Qwen3-8B-Base`; records that the documented Qwen LoRA example reports 22 GB GPU memory without treating that figure as universal; and records that llama.cpp native training remains WIP/limited and does not establish a Qwen3-8B production training path.

## Review and completion evidence

Initial independent Luna/High review returned REVISE for two documentation issues: the Qwen revision URL/checkpoint wording conflated post-trained and base checkpoints, and the llama.cpp LoRA conversion wording incorrectly implied actual base weights were required for adapter conversion.

The report was revised to use the correct `Qwen/Qwen3-8B` revision, explicitly distinguish `Qwen/Qwen3-8B` from `Qwen/Qwen3-8B-Base`, and state precisely that `convert_lora_to_gguf.py` requires base-model configuration/metadata for adapter conversion while base artifacts are separately required for merging/applying or inference validation.

Independent re-review returned PASS. All eight acceptance criteria passed. `git diff --check` passed. No production code, architecture decision, dependency, model, dataset, download, installation, training, default-model behavior, benchmark semantics, or runtime behavior changed.
