# M04-002 — Add read-only Controller recovery choice

**Status:** Done
**Milestone:** M04 — Recovery intelligence

## Objective

Use the M04-001 `RecoveryObservation` / `RecoveryInspection` boundary to let the local Controller recommend one legal recovery operation, or explicitly request operator judgment when no safe choice is justified.

This task is read-only. It introduces recovery judgment, not recovery execution.

## Required path

```text
RecoveryObservation + legal recovery operations
                    ↓
          LocalInferenceRuntime
                    ↓
        RecoveryRecommendation
                    ↓
      typed validation against the
      inspected legal-operation set
```

The kernel remains authoritative for legality. The Controller may choose only among operations already reported legal by M04-001, or choose `operator_decision`.

## Scope

- Add a bounded model-independent structured `RecoveryRecommendation` contract.
- Build a recovery-specific inference request from `RecoveryInspection`; do not expose raw database/storage/provider/runtime state.
- Permit recommendation of only the repository-grounded M04-001 operations:
  - `Requeue`
  - `ResumeRevision`
  - `AcknowledgeNonConvergence`
  - or `OperatorDecision`.
- Deterministically reject a model recommendation for any operation not currently legal in the supplied inspection.
- Keep rationale/confidence bounded and advisory; they must never authorize behavior.
- Add deterministic fake-runtime tests for recommendation parsing, legal-choice validation, illegal-choice rejection, and operator-decision fallback.
- Add a small recovery decision-quality evaluation set covering the abnormal states established by M04-001.
- Run the real local Qwen evaluation only after deterministic tests pass, because this task introduces new production recovery prompt/schema semantics.

## Required decision scenarios

At minimum evaluate:

1. Blocked revision with valid actionable REVISE lineage → prefer `ResumeRevision`, not generic requeue.
2. Exact non-convergence acknowledgement condition → `AcknowledgeNonConvergence` when that is the relevant legal recovery.
3. Canonically requeueable abnormal task with no preserved revision lineage → `Requeue` when justified by the supplied facts.
4. Dependency-blocked task with no legal recovery operation → `OperatorDecision`.
5. Infrastructure failure with no repository-supported deterministic repair operation → `OperatorDecision`.
6. No eligible agent / economy exhaustion where no M04-001 recovery operation resolves the constraint → `OperatorDecision`.
7. Ambiguous/inconsistent or empty legal-operation set → `OperatorDecision`.

If a repository fixture makes one expected action invalid under actual M04-001 legality, correct the fixture/expectation to canonical behavior rather than weakening legality.

## Constraints

- Reuse `RecoveryObservation`, `RecoveryInspection`, `RecoveryOperation`, and the existing `LocalInferenceRuntime` structured-output boundary.
- Do not duplicate recovery legality in Controller code.
- Do not infer an executable action from free-form rationale/text.
- Do not allow the model to manufacture new recovery operation names, task IDs, commands, paths, SQL, provider payloads, worker handles, or authorization.
- Recommendation must be validated against the exact inspected legal-operation set before being considered actionable.
- `OperatorDecision` is always non-mutating and must remain available when the model cannot justify a legal recovery.
- Do not execute recovery in this task.
- Do not mint or reuse M03 normal-action authorization for recovery.
- Do not add inference → action → inference loops.
- Do not change deterministic validation truth or revision lineage.
- Keep the existing M03 normal-action recommendation path unchanged.

## Non-goals

- Recovery execution or authorization.
- Automatic continuation/retry loops.
- Adding new recovery operations beyond M04-001.
- Dependency mutation/repair.
- Agent/model/economy escalation execution.
- Broad removal of old recovery policy.
- Planning/Lead migration.
- Memory.
- CLI/TUI/desktop UX.
- Model replacement, GPU work, or Python.

## Dependencies

- M04-001 complete and source-reviewed `PASS`.
- M02 structured local inference contract remains the model/runtime boundary.

## Acceptance criteria

1. A bounded structured recovery recommendation type exists and is independent of Qwen/llama.cpp/native backend details.
2. Recovery inference receives only bounded M04-001 observation/legal-operation facts.
3. A recommended recovery operation is accepted only when that exact operation is legal in the supplied `RecoveryInspection`; illegal/model-invented choices are rejected deterministically.
4. `OperatorDecision` remains a typed non-executable fallback and is used for states with no safe legal recovery.
5. Deterministic fake-runtime tests cover legal choices, illegal choices, malformed output, operator fallback, and zero mutation.
6. The required abnormal decision scenarios are evaluated without changing M04-001 legality to make the model pass.
7. Recovery recommendation performs no mutation, mints no authorization, and introduces no continuation loop.
8. Existing M03 normal-action behavior remains unchanged.
