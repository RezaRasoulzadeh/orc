# M05-003 — Persist Controller Plan proposals through explicit authorization

**Status:** Done
**Milestone:** M05 — Planning and Lead unification

## Objective

Connect a validated M05-001 Controller plan result to the M05-002 canonical Controller-origin Plan storage seam through explicit trusted one-shot authorization.

## Result

Implemented `ControllerPlanPersistenceProposal::from_controller_result`, `OrcApp::authorize_controller_plan_persistence`, and `OrcApp::execute_authorized_controller_plan_persistence`, reusing `Database::store_controller_plan` as the canonical persistence seam.

Authorization is private-field, non-serializable, non-cloneable, consumed by value, and bound to the exact project ID and complete `PlanResponse`. Execution checks authorization matching and freshly validates the proposal immediately before canonical persistence.

Successful execution persists exactly one Controller-origin `Proposed` Plan. It consumes no Lead decision and invokes no Planner run, worker, task creation, plan review, approval, or application.

Execution results are bounded and typed for authorization rejection, fresh validation rejection, canonical persistence failure, or persisted Plan evidence.
