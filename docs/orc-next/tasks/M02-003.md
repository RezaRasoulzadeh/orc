# M02-003 — Enforce reliable structured Controller output

**Status:** In progress — strict output proven; one semantic evaluation failure remains
**Milestone:** M02 — Read-only Controller

## Objective

Make local Controller structured responses conform reliably to their declared
JSON contract, without weakening safety by silently accepting arbitrary
trailing model output.

## Why

M02-002 showed that the local Qwen3 baseline selected the intended semantic
action in all seven representative states, but only 4/7 responses satisfied the
strict structured-output contract. Valid JSON followed by extra prose or
repeated JSON is a protocol failure, not evidence that the Controller may
silently strip or ignore untrusted output.

## Scope

- Inspect the grammar/schema-constrained decoding capabilities available in the
  pinned `llama-cpp-2` / llama.cpp integration before selecting an implementation
  mechanism.
- Prefer native grammar/schema-constrained decoding when the pinned native
  version supports it.
- Keep grammar, schema and backend mechanics inside the local runtime adapter.
- Preserve the existing model-independent Controller and
  `LocalInferenceRuntime` boundaries; extend generic structured-output request
  semantics only if the investigation proves it necessary.
- Keep strict parsing authoritative: trailing prose, repeated JSON or otherwise
  malformed output remains a failed structured response.
- Add deterministic tests for valid structured output and malformed/trailing
  output behavior.
- Add an opt-in Qwen3 evaluation proving all seven existing M02-002 scenarios
  satisfy both semantic expectations and the strict structured contract.

## Integration constraints

- Do not add Qwen-specific logic to Controller or domain types.
- Do not solve protocol failures with regex, prose stripping or blindly taking
  the first `{...}` object from malformed output.
- Keep the Controller read-only; no lifecycle mutation, dispatch/review/revise/
  recovery execution, tools, memory, planning/Lead migration, scheduler or GPU
  work.
- Do not download or commit model weights, add Python dependencies or create a
  second inference/runtime boundary.
- Preserve the distinction between semantic decision quality and strict
  structured-output compliance in evaluation reports.

## Non-goals

- Do not add mutation-capable Controller tools or action execution.
- Do not change lifecycle legality, persistence, validation execution, economy
  resolution, planning/Lead behavior or memory.
- Do not relax the declared JSON contract to improve the score.
- Do not implement fallback natural-language interpretation.

5. The ignored, feature-gated Qwen3 evaluation runs the seven unchanged

## Implementation status

Implemented the native structured-output path behind the existing local
runtime boundary. The pinned `llama-cpp-2 = 0.1.155` binding's `common`
feature provides `json_schema_to_grammar`; `LlamaCppRuntime` converts the
model-independent JSON schema into llama.cpp grammar text and installs it as a
`LlamaSampler::grammar` sampler before the final greedy or distribution
sampler. The grammar, sampler and native handles remain private to
`src/local_runtime/llama_cpp.rs`.

`LocalInferenceParameters` now carries the generic
`LocalInferenceResponseFormat::JsonSchema { schema }` request option (default
remains plain text). The adapter parses structured responses as exactly one
complete JSON value. Invalid, trailing or repeated output is rejected with a
typed `InvalidStructuredOutput` error retaining the raw output and parse
error. The `LocalInferenceRuntime::infer` trait signature is unchanged; the
generic parameters and error surface are the only runtime-boundary additions.
Controller recommendation validation also rejects missing required fields,
unknown fields and inconsistent action/operator-decision values.

Deterministic tests cover schema bounds, native schema-to-grammar conversion,
strict valid/trailing/repeated JSON handling, invalid fields, typed semantic
interpretation and retention of raw structured-output failure evidence. The
initial native grammar smoke exposed a sampler-contract bug rather than a
schema or tokenizer incompatibility: pinned `llama-cpp-2 = 0.1.155` already
samples and accepts the selected token inside `LlamaSampler::sample`, while
the adapter was accepting that token a second time. The duplicate acceptance
emptied the native grammar stack; the subsequent grammar application reached
llama.cpp's `!stacks.empty()` assertion. The explicit post-sample acceptance
was removed, leaving native sampling as the single acceptance path. A minimal
ignored structured-runtime smoke now exercises this path without changing the
seven-scenario evaluation.

## Real-model acceptance run

After the sampler fix, the full seven-scenario Qwen3 evaluation completed in
`155.64s` without a grammar crash. Strict structured-contract compliance was
`7/7`, proving the native grammar path solved the protocol failure. Semantic
decision quality was `6/7`.

The sole semantic failure was `review-revise`. Canonical state supplied:

- lifecycle: `RevisionRequired`;
- phase: `RevisionRequired`;
- canonical `next_step`: `revise`;
- current Review verdict: `REVISE`;
- violated criterion with current lineage/evidence;
- prior implementation execution present.

The model returned a valid structured operator decision instead of the required
revision action:

```json
{
  "suggested_next_step": null,
  "decision_class": "operator_decision",
  "rationale": "The validation evidence indicates a violation of the bounded criterion, necessitating a revision."
}
```

This is a semantic selection failure, not a parsing/schema failure. Scenario
expectations remain unchanged.

## Revision contract

The remaining work must stabilize the model-independent Controller decision
contract without overfitting the `review-revise` fixture or weakening the
semantic gate.

1. Inspect the current Controller prompt and inference parameters before
   changing code. Treat `OperationalNextStep` and lifecycle/review facts as
   canonical kernel observations, not mere suggestions.
2. Make the prompt contract explicit about the distinction between an action
   recommendation and an operator decision: when canonical state exposes a
   clear actionable next step and the packet contains no conflicting facts,
   return that action; reserve `operator_decision` for genuinely ambiguous,
   inconsistent or non-actionable state.
3. Do not hardcode scenario IDs, task IDs, Review verdict strings or a special
   `RevisionRequired -> revise` branch in model/runtime code. The rule must be
   generic and model-independent.
4. Do not simply force-copy `next_step` into the response. The Controller must
   still reason over abnormal cases such as blocked validation-repair exhaustion
   and infrastructure failure; the seven existing scenarios and expectations
   remain unchanged.
5. Keep structured grammar/schema behavior, sampler mechanics and strict full
   parsing unchanged unless evidence shows a regression there. Strict contract
   compliance is already proven `7/7`.
6. Add deterministic prompt/request tests proving the decision policy is stated
   generically and that the structured schema/response contract is unchanged.
7. Run focused deterministic tests and normal validation first. Only after
   review of the narrow change, rerun the seven-scenario real-model evaluation
   once. Acceptance still requires `7/7` semantic and `7/7` strict compliance.

Do not begin M03-001 until this task reaches those acceptance results.
