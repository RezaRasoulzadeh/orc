# M05-004 — Add read-only Controller Plan review judgment

**Status:** Planned
**Milestone:** M05 — Planning and Lead unification

## Objective

Move Plan review judgment from the legacy Lead model path into the local Controller as a bounded, read-only capability, without yet changing canonical Plan review persistence, status transitions, revision execution, approval, or application.

This is the next judgment seam after M05-003: Controller-origin Plans can now be proposed and persisted safely, but `OrcApp::review_plan_with_backend_and_resolution` still asks the legacy Lead backend to decide `APPROVE`, `REVISE_PLAN`, or `USER_DECISION_REQUIRED`.

## Current repository seam

The existing Plan review path:

1. loads a persisted Plan;
2. verifies it is the current valid Plan;
3. builds a review prompt, optionally including persisted operator resolution;
4. invokes the legacy Lead backend;
5. accepts only `Approve`, `RevisePlan`, or `UserDecisionRequired`;
6. finds the persisted Lead decision for that run;
7. calls `Database::record_plan_review`, which owns durable Plan review/status transitions.

M05-004 migrates only step 4's semantic judgment into the Controller and returns a typed read-only result. Steps 5–7 remain legacy/canonical until a later task explicitly migrates persistence.

## Required path

```text
current valid persisted Plan + bounded review context
                    ↓
       Controller Plan review request
                    ↓
          LocalInferenceRuntime
                    ↓
       typed Controller review result
                    ↓
                 no mutation
```

## Scope

- Inspect `OrcApp::review_plan_with_backend_and_resolution`, `Database::record_plan_review`, `PlanReview`, Plan status transitions, current-valid-plan checks, `LeadDecisionKind`, existing Controller inference patterns, and Plan review/workflow tests before editing.
- Define a bounded, model-independent Controller Plan review request containing only facts needed for semantic review: canonical persisted Plan content/identity/status/provenance as needed, bounded project/review context, and optional operator resolution when supplied.
- Define a dedicated typed Controller Plan review decision. It must represent only the currently valid review outcomes: approve, revise plan, or operator/user decision required. Do not expose unrelated Lead decision kinds.
- Define a bounded typed review result carrying the decision plus concise structured details/revision feedback needed by later persistence/revision work.
- Add a read-only Controller Plan review builder/service using `LocalInferenceRuntime`, following M02/M04/M05-001 structured-output boundaries.
- Add an `OrcApp` read-only entry point that first loads the requested Plan and deterministically verifies it is the current valid Plan before inference.
- Do not call `Database::record_plan_review` from the new Controller path.
- Do not persist Lead decisions, Plan reviews, approval, revision requests, or user-decision records from the new Controller path.
- Add deterministic fake-runtime tests for all three decisions, invalid structured output, missing/non-current Plan rejection before inference, bounded request construction, and proof of no mutation.
- Add one ignored real-model evaluation/smoke test covering representative Plan review scenarios if production review prompt/schema/parser semantics are introduced or changed by this task.

## Preserve

- `Database::record_plan_review` as the canonical durable review/status-transition mechanism for now.
- Existing `PlanReview` persistence schema and semantics.
- Existing Plan status transitions.
- Existing legacy `review_plan_with_backend[_and_resolution]` behavior and CLI/workflow compatibility.
- Existing Controller Plan proposal/persistence behavior from M05-001 through M05-003.
- Approved-plan application/task creation semantics.
- Deterministic current-valid-plan checks.

## Constraints

- Read-only only: the Controller review result must not mutate Plan, review, Lead, workflow, task, or worker state.
- Controller review result is judgment, not authorization and not a persisted review.
- Do not map the result into a fake `LeadDecisionKind` persistence record merely to reuse legacy lineage.
- Do not fabricate Lead runs or Lead decision IDs.
- Do not call `record_plan_review` from the Controller path.
- Do not approve/apply a Plan.
- Do not create tasks.
- Do not execute Plan revision.
- Do not remove or rewrite legacy Lead Plan review yet.
- Do not broaden Plan review outcomes beyond approve/revise/operator-decision.
- Do not expose SQLite, Git/worktree mutation, shell, credentials, or worker execution to the Controller.
- No autonomous planning/review loop.
- No Qwen-specific core/domain behavior.
- No Python.

## Non-goals

- Persisting Controller Plan review decisions.
- Authorized Plan approval/revision transitions.
- Controller Plan revision generation.
- Applying approved Plans.
- Removing Lead Plan review.
- Removing Planner/Lead roles or workflow stages.
- DIRECT_TASKS migration.
- General Lead/user-decision migration.
- Memory/autonomy/UI work.

## Acceptance criteria

1. A current valid persisted Plan can be projected into a bounded Controller Plan review request without mutation.
2. The Controller returns exactly one typed decision: approve, revise plan, or operator/user decision required, with bounded structured details.
3. Missing or non-current Plans are rejected deterministically before local-model inference.
4. Invalid/unrecognized model output fails closed and produces no durable mutation.
5. The new Controller review path creates no Lead run/decision, PlanReview, Plan status change, task, workflow transition, approval/application, or revision execution.
6. Optional operator resolution is bounded and included only as review context; it does not itself authorize or mutate anything.
7. Existing legacy Lead Plan review/persistence/status-transition behavior remains unchanged.
8. Deterministic fake-runtime tests cover all outcomes and failure/no-mutation behavior; real-model evaluation passes if production review inference semantics are introduced.
