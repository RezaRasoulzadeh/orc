# M08-004 — Add explicit typed curation for Controller planning results

**Status:** Planned
**Milestone:** M08 — Experience dataset

## Objective

Add one capability-local curation adapter for an already-produced Controller planning interaction, projecting the existing typed `ControllerPlanningInput` and existing canonical `ControllerPlanResult` into one M08-001 experience example under explicit trusted verification metadata.

This extends the proven M08-002/M08-003 pattern to planning without introducing a generic experience-capture framework, automatic harvesting, or workflow-derived labels.

## Repository-grounded context

Controller planning already has a complete typed reasoning boundary in `src/controller_planning.rs`:

- `ControllerPlanningInput` contains the bounded canonical planning request plus bounded advisory memory and exposes `validate()`;
- `ControllerPlanResult` contains the proposed canonical `PlanResponse`, rationale, and optional uncertainty and exposes `validate()`;
- `PlanResponse` remains the canonical plan protocol nested inside the Controller result.

M08-001 provides the sole global experience-record persistence format. M08-002 and M08-003 established that each reasoning capability should use a narrow typed adapter over its existing production input/output contract rather than a universal capture object.

## Scope

Add one planning-specific typed curation request and the smallest `OrcApp` API needed to persist one explicitly verified planning example.

The request must accept:

- one existing `ControllerPlanningInput`;
- one observed `ControllerPlanResult`;
- one explicit accepted/expected `ControllerPlanResult`;
- explicit `ControllerExperienceVerificationBasis`;
- explicit M08-001 outcome and quality metadata;
- optional M08-001 provenance;
- correction metadata only when observed and accepted canonical outputs differ.

Do not accept a caller-controlled capability identifier.

## Canonical capability

Use fixed code-owned capability identifier:

`controller.plan_generation`

The caller must not be able to override it.

## Canonical input projection

The exact supplied `ControllerPlanningInput` is the dataset input authority.

Before projection:

- call its existing `validate()`;
- serialize the exact typed value deterministically;
- do not rebuild a second planning input schema;
- do not summarize, reorder, enrich, truncate, or infer additional project/workflow state;
- do not replace its embedded bounded memory or current request with later state.

No planning inference call is permitted in this adapter.

## Canonical output projection

The existing `ControllerPlanResult` is the dataset output authority.

Observed and accepted values must both pass the production `ControllerPlanResult::validate()` contract.

Persist the exact accepted `ControllerPlanResult` JSON as M08 `accepted_output`, including:

- exact canonical `PlanResponse`;
- exact bounded rationale;
- exact optional uncertainty.

Do not persist only the nested `PlanResponse` while discarding Controller reasoning metadata. Do not substitute persisted Plan identity/status, Plan review outcome, task application result, workflow state, or free-form prose for the reasoning output.

## Provenance

M08-001 provenance remains optional, explicit, and non-owning.

`ControllerPlanningInput` currently carries project name rather than canonical project ID, so M08-004 must not invent a deterministic project-ID lookup or require inferred provenance consistency merely to fill metadata.

If provenance is supplied, validate it only through existing M08-001 rules. Do not query project/workflow state to synthesize missing provenance.

## Correction semantics

Compare exact canonical serialized observed and accepted `ControllerPlanResult` values.

If observed == accepted:

- correction metadata must be absent;
- outcome must satisfy valid non-correction M08-001 semantics;
- no correction evidence is manufactured.

If observed != accepted:

- outcome must be `Corrected`;
- explicit valid correction metadata is required;
- `correction.original_output` must exactly equal the canonical observed `ControllerPlanResult` JSON;
- M08 `accepted_output` must exactly equal the canonical accepted `ControllerPlanResult` JSON.

Do not infer correction because a Plan was later revised, rejected, persisted differently, failed review, or produced different downstream tasks.

## Verification boundary

Verification remains explicit and caller-owned.

Do not automatically treat any of these as sufficient verification:

- Plan persistence success;
- Plan review approval;
- task application success;
- workflow advancement;
- validation/review success;
- operator acceptance;
- eventual task completion.

These may be evidence used by a future explicit curation policy, but M08-004 must not derive labels from them.

## Production order

1. validate exact `ControllerPlanningInput`;
2. validate observed `ControllerPlanResult`;
3. validate accepted `ControllerPlanResult`;
4. deterministically project exact input/observed/accepted JSON;
5. enforce correction semantics;
6. construct exactly one `ControllerExperienceExampleDraft` with fixed capability;
7. delegate verification/outcome/quality/provenance/bounds validation to M08-001;
8. persist only through existing `OrcApp::create_controller_experience_example(...)`.

At most one row may be written per call. Any validation/projection failure must write zero rows.

## Invariants / requirements

- Planning result curation only; no generic experience adapter.
- Explicit trusted call only.
- No Controller inference.
- No automatic capture/harvesting.
- No planner/workflow/Plan-review hook.
- No automatic verification or correction inference.
- Fixed code-owned capability identity.
- Exact canonical `ControllerPlanningInput` preserved as dataset input.
- Exact canonical `ControllerPlanResult` preserved as accepted output.
- Existing planning prompt/schema/parser/bounds remain unchanged.
- M08-001 remains sole persistence format.
- Runtime `MemoryKind::Experience` remains unchanged.
- No provider/model-specific behavior, provider token hard cap, embeddings, Python, export, splitting, balancing, or training.

## Non-goals

- Automatic planning-call capture.
- Automatic curation from Plan persistence/review/workflow outcomes.
- Intake, Plan review, Plan revision, or memory-judgment curation yet.
- Generic curation framework.
- Dataset export/trainer formats.
- Dataset deduplication/ranking/sampling/balancing/splitting.
- Fine-tuning/evaluation runner changes.
- Runtime memory changes.

## Acceptance criteria

1. One explicit application API persists one verified Controller planning interaction as one M08-001 example.
2. Capability identity is fixed as `controller.plan_generation` and not caller-controlled.
3. Dataset input is the exact validated `ControllerPlanningInput` projection.
4. Dataset accepted output is the exact validated `ControllerPlanResult` projection.
5. Observed and accepted values use the existing production planning validation contracts.
6. Equal outputs create non-correction examples; differing outputs require explicit corrected outcome and exact observed-output correction metadata.
7. Invalid/mismatched/unbounded data creates zero rows.
8. Successful curation creates exactly one row through M08-001 only.
9. No planning inference/workflow behavior changes and no automatic harvesting/verification is introduced.
