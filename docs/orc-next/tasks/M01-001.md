# M01-001 — Introduce the model-independent local runtime boundary

**Status:** Done
**Milestone:** M01 — Native model runtime

## Objective

Add the smallest native inference abstraction needed by the future Controller without coupling Orc domain/application code to Qwen, GGUF or llama.cpp details.

## Why

The local model is an implementation dependency, not part of Orc's domain model. Establishing the boundary first prevents a future model/runtime replacement from requiring Controller, memory or lifecycle reimplementation.

## Scope

- Inspect current Rust dependency/build/runtime patterns before selecting the concrete llama.cpp integration mechanism.
- Define a small model-independent request/response/error/configuration boundary for local inference.
- Keep model path, context/inference settings, prompt formatting and backend-specific setup outside Controller/domain types.
- Provide a deterministic fake/test implementation so normal tests do not require model weights.
- Define how the native llama.cpp adapter will plug into the boundary.
- Keep this task narrowly focused on the seam; concrete real-model integration may be split into M01-002 if review shows that is safer.

## Non-goals

- Do not build `ControllerStatePacket` yet.
- Do not grant lifecycle/database mutations.
- Do not add memory.
- Do not remove Lead/Planner.
- Do not redesign worker-provider abstractions to force reuse if their semantics do not fit local inference.
- Do not introduce Python.
- Do not download/commit model weights as part of deterministic tests.

## Dependencies

- M00-001.

## Acceptance criteria

1. Runtime-facing Controller/domain code has no Qwen-, GGUF- or llama.cpp-specific types.
2. A bounded inference request can be submitted through one explicit local-model runtime interface and returns a typed response or typed failure.
3. Configuration distinguishes model/runtime concerns from Controller/domain concerns.
4. Deterministic tests use a fake runtime and require no model file/network access.
5. The concrete llama.cpp integration point is documented and can be replaced without changing Controller state/action types.
6. No Python runtime dependency is added.

## Required tests/evidence

- Unit tests for request/response/error propagation through the runtime boundary.
- Test proving backend-specific configuration does not leak into Controller/domain types.
- `cargo fmt --check` and focused Rust tests for changed modules.

## Result

Implemented in `src/local_runtime.rs` and exported from `src/lib.rs`.

The boundary provides bounded `LocalInferenceRequest` values, typed text or
structured `LocalInferenceResponse` values, typed runtime/request failures,
and `LocalRuntimeConfig` for model location and native runtime settings. The
`LocalInferenceRuntime` trait is the integration point for the future
llama.cpp/GGUF adapter; no model-family, tokenizer, native handle, Controller
state, lifecycle, database, or provider type crosses the boundary.

Five deterministic unit tests exercise response propagation, typed backend
failure propagation, request bounds, configuration separation, and
filesystem-independent configuration validation. No model file, network, or
Python dependency is used.
