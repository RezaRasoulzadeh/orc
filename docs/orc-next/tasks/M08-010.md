# M08-010 — Add explicit typed curation for Controller memory maintenance target selection

**Status:** Planned
**Milestone:** M08 — Experience dataset

## Objective

Add one capability-local curation adapter for an already-produced Controller memory-maintenance target-selection judgment, projecting the exact typed `ControllerMemorySelectionInput` and canonical `ControllerMemorySelectionResult` into one M08-001 experience example under explicit trusted verification metadata.

This task curates target-selection judgment only. Deterministic candidate construction, later target re-resolution, maintenance judgment, grant inspection, mutation execution, and durable memory state remain separate boundaries.

## Repository-grounded context

`src/controller_memory_selection.rs` exposes a clean bounded read-only reasoning boundary:

- `ControllerMemorySelectionInput` contains current project ID, exact explicit current facts, the bounded deterministic candidate projection, and omission/count metadata;
- input validation enforces positive current project identity, exact metadata consistency, unique candidate identities, current-project Project/Episodic scope, Active lifecycle, canonical provenance/confidence, and production candidate/input bounds;
- `ControllerMemorySelectionResult` is exactly `NoTarget` or `SelectTarget { target }`;
- production `ControllerMemorySelectionResult::validate(input)` requires any selected target to be one exact supplied candidate;
- candidate enumeration from `MemoryService` is deterministic application work before inference and is not part of the model output;
- later maintenance judgment separately decides Keep/Correct/Supersede/Remove.

## Scope

Add one memory-selection-specific typed curation request and the smallest `OrcApp` API needed to persist one explicitly verified selection judgment.

The request must accept:

- one existing `ControllerMemorySelectionInput`;
- one observed `ControllerMemorySelectionResult`;
- one explicit accepted/expected `ControllerMemorySelectionResult`;
- explicit `ControllerExperienceVerificationBasis`;
- explicit M08 outcome and quality metadata;
- M08 provenance through the existing M08-001 type;
- correction metadata only when observed and accepted canonical outputs differ.

Do not accept a caller-controlled capability identifier.

## Canonical capability

Use fixed code-owned capability identifier:

`controller.memory_selection`

## Canonical input projection

The exact supplied `ControllerMemorySelectionInput` is the dataset input authority.

Before projection:

- call production `ControllerMemorySelectionInput::validate()`;
- serialize the exact typed input deterministically;
- preserve exact `current_project_id`;
- preserve exact `current_request.current_facts`;
- preserve exact candidate order and candidate fields;
- preserve exact `eligible_candidate_count`, `selected_candidate_count`, and `omitted_candidate_count`;
- do not enumerate memory again;
- do not rebuild, resort, refresh, add, remove, or replace candidates;
- do not derive facts from workflow/task/log state;
- do not summarize, enrich, truncate, or infer omitted candidates.

No selection inference call is permitted in the curation adapter.

## Canonical output projection

The existing `ControllerMemorySelectionResult` is the dataset output authority.

Observed and accepted values must both pass production validation against the exact supplied input:

`ControllerMemorySelectionResult::validate(&input)`

Persist exact accepted result JSON as M08 `accepted_output`.

For `NoTarget`, preserve the canonical result exactly.

For `SelectTarget`, preserve the exact `MemoryId`. Production validation remains authoritative that the target must be one exact identity present in `input.candidates`.

Do not replace the reasoning result with:

- selected candidate record contents;
- refreshed target state;
- maintenance request/input/result;
- maintenance grant result;
- mutation intent/execution outcome;
- selected-target composed-step result;
- free-form explanation.

## Candidate-construction boundary

The already-supplied input is authoritative for the reasoning example.

M08-010 must not call `input_from_memory_service(...)`, enumerate storage, or reconstruct the deterministic candidate set during curation. Candidate order, omission metadata, and bounded truncation are part of the exact inference input and must be preserved as supplied.

Do not infer that an omitted candidate should have been selected. Omitted candidates are not selectable in the observed inference boundary.

## Correction semantics

Compare exact canonical serialized observed and accepted `ControllerMemorySelectionResult` values after validating both against the same exact input.

If observed == accepted:

- correction metadata must be absent;
- outcome must satisfy valid non-correction M08-001 semantics.

If observed != accepted:

- outcome must be `Corrected`;
- explicit valid correction metadata is required;
- `correction.original_output` must exactly equal the canonical observed selection result JSON;
- M08 `accepted_output` must exactly equal the canonical accepted selection result JSON.

Valid explicit corrections may include:

- `NoTarget` -> one valid supplied candidate;
- one valid supplied candidate -> `NoTarget`;
- one valid supplied candidate -> a different valid supplied candidate.

Both observed and accepted must independently pass production validation against the same exact input.

## Verification boundary

Verification remains explicit and caller-owned.

Do not automatically infer verification/correction from:

- later target re-resolution;
- later maintenance judgment;
- grant issuance;
- mutation execution;
- resulting memory lifecycle/state;
- workflow/task success or failure;
- the fact that a selected candidate still exists later.

## Production order

1. validate exact `ControllerMemorySelectionInput`;
2. validate observed `ControllerMemorySelectionResult` against that input;
3. validate accepted `ControllerMemorySelectionResult` against that input;
4. deterministically project exact input/observed/accepted JSON;
5. enforce correction semantics;
6. construct exactly one `ControllerExperienceExampleDraft` with fixed capability;
7. delegate M08 metadata/bounds validation to M08-001;
8. persist only through existing `OrcApp::create_controller_experience_example(...)`.

Any failure must write zero rows. Success writes exactly one row.
